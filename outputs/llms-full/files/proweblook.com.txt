## 3. Phone Number Validator API

### Overview
Validate and enrich phone numbers globally. The API reports whether a number is valid and, for confirmed numbers, returns its carrier, line type, location, country, national/international formatting, timezones, and current rate-limit information.

### Endpoint
```
GET or POST https://lookup.proweblook.com/api/v1/phonevalidation
```

Responses use JSON.

### Authentication
- GET: send `api_key` as a query parameter.
- POST: send `api_key` in the JSON or form body.
- No API-key header or Bearer-token authentication is documented for this endpoint.
- Keep API keys out of client-side code, public repositories, and logs.

### Parameters
| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `phone_number` | string | Yes | A full international number, preferably E.164 (for example, `+14155552671`), or a local/national number accompanied by `country_code`. |
| `api_key` | string | Yes | Your ProWebLook API key. Use the query string for GET and the request body for POST. |
| `country_code` | string | No | ISO 3166-1 alpha-2 country hint such as `US`, `IN`, or `GB`. Omit it or send the literal `none` to auto-detect the country from a full international number. |

### Phone-number and country-code rules
- If `country_code` is omitted or set to `none`, `phone_number` must include the international country calling code, preferably in E.164 form: `+14155552671`.
- If `phone_number` is local or national, provide the ISO country hint: `phone_number=9876543210&country_code=IN`.
- `country_code` is a two-letter ISO country identifier such as `IN`; it is not a numeric calling prefix such as `+91`.
- In a GET URL, percent-encode the leading `+` as `%2B`. Otherwise, some URL decoders interpret it as a space.
- The published contract does not define extension, separator, whitespace, or normalization rules; E.164 is the safest input format.

### GET Request — international number
```bash
curl "https://lookup.proweblook.com/api/v1/phonevalidation?api_key=YOUR_API_KEY&phone_number=%2B14155552671"
```

### GET Request — local number with country hint
```bash
curl "https://lookup.proweblook.com/api/v1/phonevalidation?api_key=YOUR_API_KEY&phone_number=9876543210&country_code=IN"
```

### POST Request — JSON
```bash
curl -X POST "https://lookup.proweblook.com/api/v1/phonevalidation" \
  -H "Content-Type: application/json" \
  -d '{
    "api_key": "YOUR_API_KEY",
    "phone_number": "+14155552671"
  }'
```

POST also accepts a form body. The optional `country_code` field follows the same rules for GET, JSON, and form requests.

### Successful response fields
`status` is always the result discriminator. The enrichment fields can be absent when the number is invalid.

| Field | Type | Description |
|-------|------|-------------|
| `status` | string | `VALID_CONFIRMED` for a confirmed valid number or `INVALID` for an invalid/unconfirmed number. |
| `formatted_number` | string | Internationally formatted number. |
| `linetype` | string | Number category; see the complete values below. |
| `carrier` | string | Carrier/operator name; it may be empty for landlines. |
| `location` | string | City, region, or country description. |
| `countrycodenum` | integer | Numeric international calling code, such as `1`, `44`, or `91`. |
| `countrycode` | string | ISO 3166-1 alpha-2 country code. |
| `countryname` | string | Full country name. |
| `formatnational` | string | Nationally formatted number. |
| `formatinternational` | string | Internationally formatted number. |
| `timezone` | array of strings | Applicable IANA timezone identifiers. |
| `ratelimit_remain` | integer | Calls remaining in the current rate-limit window. |
| `ratelimit_seconds` | integer | Seconds until the current rate-limit window resets. |

Documented `linetype` values: `Mobile`, `Fixed Line`, `Fixed Line or Mobile`, `Toll-Free`, `Premium Rate`, `Shared Cost`, `VoIP`, `Personal Number`, `Pager`, `Universal Access Number`, `Voicemail`, and `Unknown`.

### Valid-number response
```json
{
  "status": "VALID_CONFIRMED",
  "formatted_number": "+1 415 555 2671",
  "linetype": "Mobile",
  "carrier": "T-Mobile",
  "location": "California",
  "countrycodenum": 1,
  "countrycode": "US",
  "countryname": "United States",
  "formatnational": "(415) 555-2671",
  "formatinternational": "+1 415 555 2671",
  "timezone": ["America/Los_Angeles"],
  "ratelimit_remain": 100,
  "ratelimit_seconds": 100
}
```

### Invalid-number response
An invalid number is a normal validation result, not an API error:

```json
{
  "status": "INVALID"
}
```

### Error responses
All documented errors contain an `error` string.

| HTTP | Meaning | Example body |
|------|---------|--------------|
| `400` | A required parameter is missing or invalid. | `{"error":"PhoneNumber is missing in the request."}` |
| `401` | The API key is missing or invalid. | `{"error":"Invalid API key."}` |
| `402` | The account has insufficient phone-validation credits. | `{"error":"Insufficient phone API credits."}` |
| `500` | An unexpected server error occurred. | `{"error":"Description of the error."}` |

### Credits and links
- **Cost:** 1 credit from `phoneapi_balance` per successful validation.
- **Balance service value:** `phonevalidation`.
- The published documentation does not specify whether a successful HTTP 200 response with `status: INVALID` consumes a credit.
- **Target Keywords:** `phonevalidator`, `phone number validator`, `phone validation api`
- **Page:** https://proweblook.com/phone-number-validator
- **Documentation:** https://docs.proweblook.com/api-reference/phone-validation

### Overview

### Endpoint
```
GET https://proweblook.com/api/v1/google_serp
```

Required: `api_key`, `query` (1–2000 characters). Optional: `domain` (default `google.com`), `country`, `language` (default `en`), `start` (multiple of 10, 0–990), `num` (10–100, default 10), `device` (`desktop` or `mobile`), `response_format` (`json` or `html`).

## Developer Integration & Code Examples

### Python
```python
import requests

api_key = "YOUR_API_KEY"
phone_number = "+14155552671"

# 1. Check WhatsApp Registration (legacy monolith path)
wa_res = requests.get(
    "https://proweblook.com/api/v1/checkwanumber",
    params={"api_key": api_key, "number": phone_number}
).json()

print("WhatsApp Active:", wa_res.get("numberstatus"))
```

### Node.js
```javascript
const axios = require('axios');

async function validatePhone(apiKey, number) {
    const res = await axios.get('https://lookup.proweblook.com/api/v1/phonevalidation', {
        params: { api_key: apiKey, phone_number: number }
    });
    console.log('Carrier:', res.data.carrier);
}

validatePhone('YOUR_API_KEY', '+919876543210');
```
