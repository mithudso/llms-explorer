## How it works

- [statement] The standalone container path runs only when derived-operation storage is supplied. It expands one container entry, moves the resulting vector into that storage, distributes the derived entries with serial routing disabled, and continues without distributing the original entry. An empty expansion follows the same continue path and contributes no writer operation; an unexpanded scalar falls through to ordinary writer assignment. ## Comparisons and alternatives

- [statement] Packedness depends on array representation, not the number of resulting operations: a scalar entry yields no expansion, a one-element packed array still requires scalarization, and an empty packed array yields an engaged optional containing an empty vector. Callers must drop the empty expansion rather than pass through the packed entry. The bulk expansion separately tracks whether any entry was packed, even when the total operation count stays unchanged. Ordinary scalar container operations bypass expansion. The scalar fixture asserts one surviving operation and no derived operations. The empty-array fixture asserts engaged empty expansions for insert and delete and checks that only the unrelated scalar insert survives writer-vector derivation. The one-element nested fixture asserts that the surviving container operation has a scalar key even though expansion leaves the operation count unchanged. ## Facts and statements

- [statement] The expansion interface requires packed container entries to become single-key entries before writer distribution. Container routing hashes the container identity with the scalar key hash, so an insert and a delete of the same key use the same hash domain; hashing a packed entry as one unit would break that correspondence. Writer assignment rejects entries whose key or value remains packed. The declared expansion contract preserves relative order and says operations touching a container key are applied by the same thread in oplog order.
