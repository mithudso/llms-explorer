# Apple Intelligence — developer-reliability-1

## Overview

Apple’s Foundation Models safety system checks inputs and outputs, and exposes separate guardrail violations and model refusals. The permissive content-transformation mode has a narrow string-generation purpose; it still permits refusal behavior and leaves structured generation under default checks. Apple tells app developers to keep Instructions trusted, treat tool results as untrusted, validate the values and permissions that reach side-effecting actions, and present a clear recovery path when generation is refused or blocked. Guardrail coverage also depends on supported languages and locales. A 2026 RSAC report describes a pre-26.4 bypass, but its 76/100 result is one team’s test and does not establish behavior across current systems.

Apple’s Evaluations framework gives developers a repeatable quality-test loop for Foundation Models features: run a feature over labeled samples, score each response with narrow metrics, aggregate results, and compare controlled changes. Apple updates the on-device SystemLanguageModel with OS releases, so teams need versioned prompt fixtures and regression runs when the system model changes. A useful suite starts with a small, reviewed set covering typical, boundary, and failure inputs; deterministic checks cover measurable rules, while calibrated model judges score qualitative criteria. Keep ordinary tests for state and persistence, and inspect per-case results with aggregates. Xcode 27 is generally released and Apple lists Xcode 27 and OS 27 availability for Evaluations, but an independent guide calls the APIs Beta while Apple’s Markdown availability metadata omits a beta marker; confirm exact symbol maturity in the shipping SDK.

Apple exposes the on-device model’s context limit through a runtime SystemLanguageModel.contextSize property. It reports a per-model session budget, including input and generated tokens, rather than a cross-version constant. Apple released token-count inspection in OS 26.4, while contextSize is back-deployed to OS 26.0. Apple says the on-device model changes with OS updates and asks developers to retest prompts. Error handling also changes across API generations: OS 26 uses LanguageModelSession.GenerationError, while OS 27 adds LanguageModelError, SystemLanguageModel.Error, and LanguageModelSession.Error. Apple documents availability checks and legacy fallbacks for apps that deploy to OS 26. Public sources still disagree on whether an on-device model always has 4,096 tokens: WWDC26 shows 8,192, and reports vary by hardware. Query the runtime value; the full device matrix remains unresolved.

Apple’s 2026 Foundation Models API accepts image attachments beside text; `.vision` is the capability contract, so apps should inspect the selected model and handle typed unsupported-capability and unsupported-content errors. The current image guide lists `CGImage`, `CIImage`, `CVPixelBuffer`, and image file URLs, and says the framework scales and converts color automatically. Apple says this is an image prompt path with no built-in video input. For budgets, inspect `contextSize`, count prompt and instruction usage, and profile request input/output in Instruments. Apple’s ~200 tokens/image figure is approximate on-device WWDC guidance. Current docs list a 27.0 availability floor, while Apple’s iOS 27 page still links beta downloads; this research does not call the API generally released.

## Core Concepts

### Foundation Models guardrails and untrusted input boundaries

- Apple says the on-device SystemLanguageModel guardrails check both the prompt sent to the model and the generated output. Apple’s safety talk counts developer instructions, user prompts, and tool calls among model inputs, and the framework raises a guardrail-violation error if an input or output fails its check.[^c1-1][^c1-5][^c1-16]
- Apple documents permissiveContentTransformations as a mode for processing potentially unsafe source text: String generation does not throw LanguageModelError.guardrailViolation, though the model may still return a refusal string. Non-String guided generation follows default guardrail behavior and can throw guardrailViolation or refusal errors, so the permissive mode changes the string-generation checks rather than disabling every safety behavior. verified-as-of: 2026-08-06[^c1-14][^c1-12][^c1-2][^c1-1][^c1-6]
- Apple documents LanguageModelError.refusal as the model refusing to answer and LanguageModelError.guardrailViolation as a safety check triggered by prompt or response content. A plain string response can itself be a refusal without a reliable programmatic marker; guided generation reports refusal with a refusal error instead. verified-as-of: 2026-10-22[^c1-13][^c1-12][^c1-3][^c1-1][^c1-6]
- Tentative: In an April 9, 2026 report, RSAC researchers said a Neural Exec payload combined with Unicode right-to-left override bypassed then-current Apple Intelligence on-device input/output filters and internal guardrails in their tests. They reported 76% success across 100 random prompts, said Apple shipped hardening in iOS 26.4 and macOS 26.4, and reported no evidence of in-the-wild exploitation. This is one lab's reported pre-fix sample, not a current bypass rate or a framework-wide failure rate. verified-as-of: 2026-04-09[^c1-10]
- Apple's Foundation Models safety guidance says on-device SystemLanguageModel guardrails check the input prompt and generated output; a violation at either point raises LanguageModelError.guardrailViolation. Apple also warns that context-dependent harms may pass both built-in safety layers, so developers should add protections tailored to their app's use case. verified-as-of: 2026-08-06[^c1-12][^c1-5]

### Foundation Models evaluation and OS regression workflow

- Apple’s Evaluations framework provides type-safe Swift APIs to run an intelligence-powered feature against samples, score responses with metrics from pass/fail checks to model-judge scoring, and aggregate results. verified-as-of: 2026-10-23[^c2-1][^c2-6][^c2-10]
- Apple’s Evaluations framework measures an app’s intelligence-powered feature against samples with developer-defined metrics and aggregates the results; Apple presents it for comparing prompt strategies, tracking quality over time, and catching regressions before release.[^c2-1][^c2-6]
- Apple’s June 2026 Foundation Models update notes say that updating to OS 27 changes the on-device model and direct developers to test prompts with the new model; the notes make the same recommendation for the OS 26.4 model change. verified-as-of: 2026-08-06[^c2-5][^c2-4]

### Foundation Models context and error version reconciliation

- Apple defines SystemLanguageModel.contextSize as the maximum token count the current model supports in one session, including input prompts and generated responses. The symbol is listed from OS 26.0 and back-deployed before 26.4, so implementations can query the platform value instead of inferring a limit from OS alone. verified-as-of: 2026-08-06[^c3-2][^c3-13][^c3-14]
- Apple lists LanguageModelError, SystemLanguageModel.Error, and LanguageModelSession.Error as OS 27 APIs. Its documentation says these types are unavailable on OS 26 and shows an availability check that falls back to LanguageModelSession.GenerationError; it also says apps built with Xcode 26 continue catching the old error until rebuilt with Xcode 27. Error handling must account for both runtime OS availability and the SDK used to build the app. verified-as-of: 2026-10-22[^c3-19][^c3-21][^c3-22][^c3-23][^c3-25]
- Apple documents three SystemLanguageModel generations aligned with OS 26.0–26.3, 26.4, and 27.0, and says the on-device model changes with OS 27 updates and prompts should be retested. This implies the runtime OS/model generation is a separate version dimension from the SDK used to build the app. verified-as-of: 2026-10-22[^c3-16][^c3-1]
- Apple defines SystemLanguageModel.contextSize as the model's maximum per-session token capacity, including both input prompts and generated responses. Apple says context-inspection and token-counting APIs were released in iOS 26.4 to help apps adapt to hardware; tokenCount(for:) can inspect instructions, prompts, and transcripts, and contextSize is annotated as back-deployed before 26.4.[^c3-17][^c3-1][^c3-3]
- The OS 26 generation uses LanguageModelSession.GenerationError, including exceededContextWindowSize, assetsUnavailable, and concurrentRequests. OS 27 separates model-generation failures into LanguageModelError (including contextSizeExceeded), on-device model errors into SystemLanguageModel.Error, and session misuse into LanguageModelSession.Error; Apple's OS 27 documentation shows availability checks that fall back to GenerationError on OS 26. verified-as-of: 2026-10-22[^c3-21][^c3-19][^c3-20][^c3-22][^c3-23]

### Foundation Models multimodal input and capability contracts

- Apple’s current guide lists CGImage, CIImage, CVPixelBuffer, and image file URLs as supported image prompt inputs. It says the framework infers whether a URL is an image from its UTType, performs needed scaling and color conversion, and can apply an explicit orientation transform. verified-as-of: 2026-10-23[^c4-1][^c4-2][^c4-11][^c4-12]
- Image support is advertised through `LanguageModelCapabilities.Capability.vision`; callers can inspect the selected model’s `capabilities` before sending an image. Apple says a request for an undeclared capability can fail with `LanguageModelError.unsupportedCapability`, and an independent Swift wrapper forwards image attachments only when the resolved model reports vision support. verified-as-of: 2026-10-23[^c4-3][^c4-4][^c4-5][^c4-13]
- Apple’s WWDC26 Group Lab said Foundation Models had no built-in video input at that time. Apple’s image guide says apps capturing images or processing video streams should use `CVPixelBuffer`; represent and process frames in the app rather than pass raw video as an image attachment. verified-as-of: 2026-06-09[^c4-9][^c4-1][^c4-15]
- Apple dates the iOS 27 and iPadOS 27 releases to 2026-09-14, while the current Attachment and LanguageModelCapabilities.Capability.vision symbols list 27.0 platform availability. Image prompting is therefore part of released OS 27 APIs as of 2026-10-23; API availability alone does not guarantee that the on-device model is ready or eligible on a particular device. (two sources) verified-as-of: 2026-10-23[^c4-16][^c4-2][^c4-4][^c4-6]

## Tools & Frameworks

- Treat retrieved pages and tool results as untrusted context. Apple’s agentic security guidance identifies tool results as injection sources and demonstrates spotlighting them in historyTransform; OWASP says labeling alone does not enforce trust and recommends validating tool arguments, enforcing caller permissions outside the model, and requiring approval for high-risk actions.[^c1-7][^c1-9][^c1-8] _(Foundation Models guardrails and untrusted input boundaries)_
- Apple's safety material identifies prompts, instructions, tool calls, and unverified external sources as safety inputs, but it does not establish a separate trust-isolation guarantee for tool-returned text. For that boundary, OWASP's MCP guidance says to treat every tool response as untrusted and validate outputs and subsequent authorization in trusted application code. (two sources) verified-as-of: 2026-10-21[^c1-12][^c1-5][^c1-15] _(Foundation Models guardrails and untrusted input boundaries)_
- Swift Testing’s EvaluationTrait records evaluation results as test attachments; Xcode stores these results in test reports, and an independent implementation documents the native .xcevalresult attachment format. verified-as-of: 2026-10-23[^c2-1][^c2-6][^c2-12] _(Foundation Models evaluation and OS regression workflow)_
- As checked on 2026-10-23, Xcode 27 is generally released and Apple’s Evaluations Markdown metadata lists Xcode 27 and OS 27 availability floors, while an independent API guide labels the framework Beta; the exact per-symbol maturity state remains unresolved. (two sources) verified-as-of: 2026-10-23[^c2-9][^c2-1][^c2-2][^c2-11] _(Foundation Models evaluation and OS regression workflow)_

- Apple introduced token-count inspection with OS 26.4. VoltaSDK reports that tokenCount(for:) overloads require OS 26.4 while contextSize is back-deployed to earlier OS 26 releases, so exact token counts and context capacity need separate availability handling. verified-as-of: 2026-06-08[^c3-1][^c3-3][^c3-14] _(Foundation Models context and error version reconciliation)_

## Methodology

- Build a small, reviewed evaluation set with categories for typical, boundary, and failure inputs; Apple documents manually written seed samples and synthetic expansion, while an independent implementation guide recommends trusting the reviewed seed before growing it.[^c2-1][^c2-10][^c2-11] _(Foundation Models evaluation and OS regression workflow)_
- Compare control and experimental runs on the same fixtures, change one variable at a time, and inspect individual responses as well as aggregate metrics before carrying a change forward.[^c2-7][^c2-10][^c2-11] _(Foundation Models evaluation and OS regression workflow)_
- Use deterministic evaluators for objectively measurable properties and model judges for qualitative criteria; compare judge scores with human ratings because a judge is another probabilistic system rather than an objective oracle.[^c2-1][^c2-10][^c2-11] _(Foundation Models evaluation and OS regression workflow)_
- Apple’s documented evaluation workflow defines the feature code as the subject, supplies ModelSample inputs, applies Metric and Evaluator measurements, aggregates metrics, and runs the evaluation through Swift Testing with the .evaluates trait.[^c2-1][^c2-6] _(Foundation Models evaluation and OS regression workflow)_
- Apple recommends categorized datasets that represent the full range of real-world use for a feature; its documentation also describes generating synthetic samples to expand a smaller manually written set.[^c2-1][^c2-6] _(Foundation Models evaluation and OS regression workflow)_
- Use code-based evaluators for measurable response properties and model-judge evaluators for subjective qualities; Apple says judge scores should correlate with human review, and its WWDC example shows that a broad judging rubric can approve output that humans consider unhelpful.[^c2-1][^c2-6][^c2-13] _(Foundation Models evaluation and OS regression workflow)_
- Apple’s prompt-update guidance says to record the prior model’s prompt output, compare it with output from the new model, and version prompts when behavior needs to differ; an app can select a prompt version using OS availability checks. verified-as-of: 2026-08-06[^c2-4][^c2-5] _(Foundation Models evaluation and OS regression workflow)_
- For interpretable release comparisons, run control and candidate changes against the same dataset, record app commit, prompt and model configuration, OS and SDK, locale, and dataset version, then inspect category-level movement as well as the aggregate score. (two sources)[^c2-13][^c2-6][^c2-14] _(Foundation Models evaluation and OS regression workflow)_
- A model judge should not be the sole release authority: 3nsofts recommends checking judge rationales and comparing scores with human labels on held-out examples, consistent with Apple’s guidance to correlate model-judge scores with human review. (two sources)[^c2-13][^c2-1][^c2-6] _(Foundation Models evaluation and OS regression workflow)_
- Apple says the system model changes when users update to OS 26.4 and OS 27, and asks developers to retest prompts after those model updates. Prompt behavior therefore needs regression checks across model versions, even when the app uses the same framework API. verified-as-of: 2026-08-06[^c3-1][^c3-13] _(Foundation Models context and error version reconciliation)_
- Apple’s context guide states that the on-device model has a 4,096-token session context and that prompts, instructions, tool definitions and results, generated schemas, and responses all consume it. `SystemLanguageModel.contextSize` exposes the selected system model’s maximum, `tokenCount(for:)` helps estimate prompt/instruction/tool usage, and Instruments reports request input and output counts. verified-as-of: 2026-10-23[^c4-7][^c4-6][^c4-8] _(Foundation Models multimodal input and capability contracts)_
- In its June 2026 Group Lab, Apple said image support did not change the on-device 4,096-token budget and estimated roughly 200 tokens per image. Treat that as approximate, dated guidance rather than a fixed cross-model image cost: a separate developer article says larger images consume more tokens and latency, and Apple recommends measuring actual requests with Instruments. (two sources) verified-as-of: 2026-06-09[^c4-9][^c4-15][^c4-7][^c4-6] _(Foundation Models multimodal input and capability contracts)_
- Check the selected model’s capabilities before sending an image: Apple defines LanguageModelCapabilities.Capability.vision as accepting image inputs in prompts and documents general capability inspection with capabilities.contains(.guidedGeneration). Applying that pattern to capabilities.contains(.vision) before dispatch is our recommendation. Check SystemLanguageModel.availability separately because it reports runtime states such as deviceNotEligible and modelNotReady. verified-as-of: 2026-10-23[^c4-3][^c4-4][^c4-6][^c4-12] _(Foundation Models multimodal input and capability contracts)_

## Practical Patterns

- Apple says Instructions take priority over prompts and warns that putting user or other unverified content in Instructions creates prompt-injection risk. Keep Instructions app-authored and treat user or external text as data; OWASP warns that prompt labels alone do not enforce a trust boundary.[^c1-16][^c1-9][^c1-8] _(Foundation Models guardrails and untrusted input boundaries)_
- Guided generation constrains output structure but does not establish semantic correctness or authorization. Apple describes generating typed structures, while FoundationModelsBench separates decodable structure from grading the values inside the response; validate values and caller permissions before downstream actions. (two sources)[^c1-16][^c1-11][^c1-9] _(Foundation Models guardrails and untrusted input boundaries)_
- Apple warns developers not to put user or unverified external content in Instructions because session instructions take precedence over later prompts and untrusted text there creates prompt-injection risk. Keep instructions developer-controlled; put external content in task data, and use fixed choices or guided generation when the app can safely narrow the accepted input or output. verified-as-of: 2026-08-06[^c1-12][^c1-5] _(Foundation Models guardrails and untrusted input boundaries)_
- OWASP advises treating model output and retrieved or tool-provided content as untrusted, enforcing permissions and parameter validation outside the model, applying least privilege, and requiring human approval for sensitive actions. Prompt labels, deny lists, or pattern filters can help screen content but do not prove that remaining text is safe or authorize a tool action. verified-as-of: 2026-10-22[^c1-9][^c1-15] _(Foundation Models guardrails and untrusted input boundaries)_
- Apple says it periodically updates the on-device SystemLanguageModel with OS releases and recommends testing prompts against new model versions, comparing outputs, and versioning prompts when behavior changes. verified-as-of: 2026-10-23[^c2-3][^c2-4][^c2-5] _(Foundation Models evaluation and OS regression workflow)_
- In a June 2026 forum answer, an Apple Frameworks Engineer said there was no model-pinning or model-version-retrieval API at that time and recommended Evaluations to catch regressions as the system model changes across OS updates.[^c2-8][^c2-3][^c2-1] _(Foundation Models evaluation and OS regression workflow)_

## Anti-Patterns

- Evaluations measure model-driven output quality and do not replace conventional deterministic tests for application state transitions, persistence, permissions, or writes.[^c2-10][^c2-11] _(Foundation Models evaluation and OS regression workflow)_
- A fixed regression set supports apples-to-apples comparisons but does not establish generalization by itself: Google’s evaluation guidance warns that tuning against fixed nightly cases can overfit and recommends a separate release exam with unseen inputs, while Apple recommends samples spanning real-world usage.[^c2-14][^c2-1] _(Foundation Models evaluation and OS regression workflow)_

## Troubleshooting

- Apple says input and output safety guardrails cover only supported languages and locales. If language detection misses a short unsupported phrase mixed into a supported-language prompt, the guardrails may miss it too; check supportsLocale and disable the affected feature or provide an alternative experience for unsupported locales.[^c1-17][^c1-16] _(Foundation Models guardrails and untrusted input boundaries)_
- Apple recommends a user-facing recovery path for guardrail errors: rephrase a built-in prompt that triggers one, and explain the limit and offer a different prompt for user-created input. A proactive feature can suppress an interruption; for a user-initiated feature, show feedback and alternatives. For a guided-generation refusal, show the refusal explanation and let the person retry.[^c1-16][^c1-5][^c1-6] _(Foundation Models guardrails and untrusted input boundaries)_
- For a user-initiated request that triggers a guardrail error, Apple recommends explaining that the feature cannot process the input and offering a different prompt or another action. For guided-generation refusal, the app can request an explanation asynchronously and fall back to refusal.debugDescription if that request fails; for string responses, design the UI to handle a refusal message that may not be distinguishable from ordinary text. verified-as-of: 2026-08-06[^c1-12][^c1-5] _(Foundation Models guardrails and untrusted input boundaries)_
- Do not accept a passing aggregate alone: inspect per-sample failures and category-level results because the same aggregate can hide a collapsed fixture distribution or a newly failing subgroup.[^c2-1][^c2-10][^c2-11] _(Foundation Models evaluation and OS regression workflow)_
- The legacy overflow case is LanguageModelSession.GenerationError.exceededContextWindowSize; the newer model error is LanguageModelError.contextSizeExceeded, whose payload exposes the model’s contextSize and the transcript tokenCount. Apple explicitly redirects legacy assetsUnavailable to SystemLanguageModel.Error.assetsUnavailable and legacy concurrentRequests to LanguageModelSession.Error.concurrentRequests, separating on-device asset failures and session misuse from model-generation errors. verified-as-of: 2026-10-22[^c3-7][^c3-6][^c3-12][^c3-10][^c3-11][^c3-27][^c3-28][^c3-29][^c3-30][^c3-31][^c3-32] _(Foundation Models context and error version reconciliation)_
- The numeric on-device context limit is not safely summarized as a universal 4,096 tokens across OS 27. Apple’s WWDC26 sample prints 8,192, while its general context guide and TN3193 still state 4,096. A third-party macOS project reports 4,096 on an M2 and 8,192 on an M3 Pro with macOS 27. Apple’s symbol docs do not publish the full hardware matrix, so apps should query contextSize and treat the exact device/model mapping as unresolved. (two sources) verified-as-of: 2026-10-23[^c3-17][^c3-3][^c3-18][^c3-26][^c3-15] _(Foundation Models context and error version reconciliation)_
- The published context-size figures are not a universal constant: Apple's general context guide states 4,096 tokens, while its WWDC26 sample prints 8,192. An apfel maintainer's 2026-10-05 correction reports 4,096 on an M2 MacBook Air running macOS 27.0.1 and 8,192 on an M3 Pro; SwiftLM likewise describes newer releases and hardware reporting larger sizes. The sources do not establish a complete OS, device, and active-model matrix, so query contextSize at runtime instead of hard-coding 4,096 or 8,192. (two sources) verified-as-of: 2026-10-05[^c3-18][^c3-3][^c3-15][^c3-13] _(Foundation Models context and error version reconciliation)_
- VoltaSDK reports that contextSize is back-deployed across OS 26.x while tokenCount(for:) overloads require the 26.4 SDK. HB Martin's migration checklist quotes Apple's note that apps built with Xcode 26 continue catching GenerationError until rebuilt with Xcode 27. Together, these sources mean compile-time SDK availability and runtime OS availability need separate gates. (two sources) verified-as-of: 2026-10-10[^c3-14][^c3-24][^c3-21][^c3-19] _(Foundation Models context and error version reconciliation)_
- Apple’s `LanguageModelError` assigns separate typed cases to `.unsupportedCapability` (the model lacks a requested feature) and `.unsupportedTranscriptContent` (the prompt contains content the model cannot process), distinguishing capability mismatch from unsupported prompt content. verified-as-of: 2026-10-23[^c4-5][^c4-3][^c4-14] _(Foundation Models multimodal input and capability contracts)_
- LanguageModelError is nonexhaustive and has distinct unsupportedCapability, unsupportedTranscriptContent, and contextSizeExceeded cases. Apple defines contextSizeExceeded as the session transcript exceeding the model’s context size and recommends trimming history or starting a fresh session. verified-as-of: 2026-10-23[^c4-5][^c4-7][^c4-3] _(Foundation Models multimodal input and capability contracts)_
