## Definitions

- [statement] mongoimport accepts JSON, CSV, and TSV input; JSON is the default. mongoexport exposes JSON and CSV output formats; its documented --type choices do not include TSV. (high confidence) — https://www.mongodb.com/docs/database-tools/mongoimport.md · keywords: mongoimport and mongoexport formats and BSON type fidelity (JSON, CSV, TSV, Extended JSON) · also: https://www.mongodb.com/docs/database-tools/mongoexport.md, https://github.com/mongodb/mongo-tools/blob/master/mongoexport/mongoexport.go
- [statement] mongoimport CSV parsing follows RFC-4180: backslashes are not escape characters, and a double quote inside a quoted field must be escaped with another double quote. (low confidence) — https://www.mongodb.com/docs/database-tools/mongoimport.md

## How it works

- [statement] mongoexport defaults to Relaxed Extended JSON v2. Use --jsonFormat=canonical when BSON type fidelity matters; mongoimport recognizes Canonical input without a corresponding import-mode flag. (high confidence) — https://www.mongodb.com/docs/database-tools/mongoimport/mongoimport-behavior.md · keywords: mongoimport and mongoexport formats and BSON type fidelity (JSON, CSV, TSV, Extended JSON) · also: https://www.mongodb.com/docs/manual/reference/mongodb-extended-json.md
- [statement] TideWave says Canonical JSON round-trips every type exactly. The Extended JSON specification explicitly limits arbitrary BSON round trips because of ordering and dollar-prefixed wrapper ambiguity; interpret the blog claim as guidance about explicit type representation, not a universal round-trip guarantee. (medium confidence) — https://tidewave.net/blog/importing-and-exporting-data-with-mongoimport-and-mongoexport · keywords: mongoimport and mongoexport formats and BSON type fidelity (JSON, CSV, TSV, Extended JSON) · also: https://github.com/mongodb/specifications/blob/master/source/extended-json/extended-json.md
- [statement] Plain JSON directly represents only a subset of BSON types. Canonical Extended JSON emphasizes type preservation; Relaxed mode emphasizes readability and interoperability and can lose type information when converted to BSON. (low confidence) — https://www.mongodb.com/docs/manual/reference/mongodb-extended-json.md

## Problems, failure modes and limitations

- [statement] mongoexport normally writes one JSON document per MongoDB document; --jsonArray writes one enclosing array. The mongoimport --jsonArray option accepts that form and its reference documents an import limit of 16 MB or smaller. (high confidence) — https://www.mongodb.com/docs/database-tools/mongoexport.md · keywords: mongoimport and mongoexport formats and BSON type fidelity (JSON, CSV, TSV, Extended JSON) · also: https://www.mongodb.com/docs/database-tools/mongoimport.md
- [statement] DRIVERS-3456 demonstrates a dollar-date field collision: an embedded document containing a date-looking string becomes a BSON Date after an Extended JSON round trip. This is an attributed encoding limitation, not evidence that every dollar-prefixed key corrupts data. (medium confidence) — https://jira.mongodb.org/browse/DRIVERS-3456 · keywords: mongoimport and mongoexport formats and BSON type fidelity (JSON, CSV, TSV, Extended JSON) · also: https://github.com/mongodb/specifications/blob/master/source/extended-json/extended-json.md
- [statement] For CSV or TSV input, --headerline uses the first row as field names; otherwise mongoimport imports that row as a document. --headerline produces an error for JSON input. (low confidence) — https://www.mongodb.com/docs/database-tools/mongoimport.md
- [statement] Extended JSON v2 cannot distinguish type-wrapper keys from user fields with the same names; DBRef is an exception to the documented warning about dollar-prefixed keys. In CSV, periods denote hierarchy, so a literal period in a field name can be misread as nesting. (low confidence) — https://www.mongodb.com/docs/database-tools/mongoimport/mongoimport-behavior.md

## Comparisons and alternatives

- [statement] mongoexport CSV requires --fields or --fieldFile to select columns. It writes field names as a header by default; --noHeaderLine suppresses that header. Use mongoimport --headerline to consume a CSV or TSV header as names rather than data. (high confidence) — https://www.mongodb.com/docs/database-tools/mongoexport.md · keywords: mongoimport and mongoexport formats and BSON type fidelity (JSON, CSV, TSV, Extended JSON) · also: https://www.mongodb.com/docs/database-tools/mongoimport.md
- [statement] Canonical Extended JSON is not an unconditional guarantee of arbitrary BSON document round trips: reserved dollar-prefixed field names can collide with type wrappers, and the specification also notes JSON object ordering differs from BSON ordering. CSV dots denote nesting and therefore can misinterpret literal dots in field names. (high confidence) — https://github.com/mongodb/specifications/blob/master/source/extended-json/extended-json.md · keywords: mongoimport and mongoexport formats and BSON type fidelity (JSON, CSV, TSV, Extended JSON) · also: https://www.mongodb.com/docs/database-tools/mongoimport/mongoimport-behavior.md

- [statement] mongoimport expects Extended JSON v2 Canonical or Relaxed input by default; use --legacy for Extended JSON v1 input. - [statement] CSV and TSV do not carry BSON type metadata. Use --columnsHaveTypes with typed fields from --fields, --fieldFile or --headerline; declarations can select string(), int32(), int64(), double(), decimal(), boolean() and date formats. The option does not apply to JSON input. - [statement] For typed CSV dates, date(<arg>) aliases date_go(<arg>) and uses a Go reference-time layout. - [statement] Canonical Extended JSON represents BSON integer types with $numberInt and $numberLong string-valued wrappers. Relaxed mode represents them as JSON integer values, so the representation does not retain that integer-width distinction. - [statement] CSV export requires an explicit field list through --fields or --fieldFile. mongoexport includes a CSV header by default; --noHeaderLine suppresses it and is valid only for CSV output. (low confidence) — https://www.mongodb.com/docs/database-tools/mongoexport.md

- [statement] For CSV or TSV type-coercion failures with --columnsHaveTypes, --parseGrace defaults to stop. Alternatives are autoCast, skipField, and skipRow; autoCast can change the resulting field type. --parseGrace has no effect for JSON input. (low confidence) — https://www.mongodb.com/docs/database-tools/mongoimport.md
