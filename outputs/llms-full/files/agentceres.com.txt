#### A memory system, not a chat buffer

Most AI tools either forget between sessions or stuff everything into context and drift into noise. Ceres's memory is structured:

- **Evidence-cited.** Every memory has provenance — source, time range, baseline, trigger reason. Auditable per-row in the dashboard.
- **Per-agent visibility.** Ceres (the Growth Officer / coordinator) sees the whole tenant; specialists see only their lane plus what Ceres promotes. No cross-talk between the Research agent and SEO agent lanes.
- **Knowledge base upload.** Drop a brand voice doc, ICP definition, or product spec; agents reference it in their next run with the source filename in the citation.
- **Per-tenant isolation.** Separate SQLite file per customer. No shared vector database, no cross-tenant query path. Memory leaks between customers are architecturally impossible.

#### Human review where it matters

Outbound content goes through your review before it ships externally:

1. **AI gathers and cites.** Specialists collect data on schedule. Every finding ships with source, time range, and baseline intact.
2. **Briefings land in your IM.** Each briefing is a readable insight, not a report you have to analyze all over again.
3. **Outbound drafts wait for you.** Cold emails, social drafts, ad variants, and creator outreach ship as drafts to your IM. You review, edit, or reject before they go live. Paid-ad spend changes always require explicit approval.

Internal collection (competitor scrapes, keyword research, citation audits) runs without per-output intervention — that's where the 24/7 cadence comes from.
