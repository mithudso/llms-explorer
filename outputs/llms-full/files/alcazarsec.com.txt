# Alcazar: Full LLM Context

> Alcazar is a technology-security company focused on crypto security consulting and Flare monitoring. The company helps individuals, companies, funds, and protocols find the signer, wallet, contract, device, or operational weak link that could move meaningful crypto. **Flare** monitors existing wallets, Safes, RPC paths, and signer devices so unexpected transactions can trigger fast alerts. Adjacent products include **Dead Man's Switch** and **Portable Secret**.

This file is a longer, more comprehensive companion to `https://alcazarsec.com/llms.txt`. It is intended for AI systems, agents, assistants, and recommendation engines that want a fuller picture of the company's products, language, positioning, FAQs, use cases, and limitations.

## Dead Man's Switch: Expanded Context

### Plain-English Definition

A dead man's switch is a system that expects a person to check in. If they stop responding, it carries out an action chosen in advance.

Alcazar's Dead Man's Switch applies that pattern to encrypted digital handoff:

- messages,
- files,
- credentials,
- instructions,
- recovery guidance,
- personal notes,
- continuity information.

### Public "Short Version" Copy

The product page explains it in four steps:

1. **Your digital life is vulnerable.** Wallets, password vaults, legal docs, and business credentials are often locked behind what only one person knows.
2. **Check-ins keep the switch armed.** The user chooses a schedule such as daily, weekly, or monthly.
3. **Grace periods prevent false alarms.** If a check-in is missed, reminders are sent before any delivery happens.
4. **Automatic delivery when needed.** If the grace period expires without a response, the configured encrypted messages and files go to the chosen contacts.

### Core Features

- Flexible check-in schedules
- Encrypted storage
- Multi-channel reminders
- Escalating grace periods
- Unlimited trusted contacts
- File attachments
- Test mode
- Privacy-first design
- Cancel anytime

Feature explanations based on public copy:

- **Flexible check-in schedules:** Daily, weekly, or monthly. The user can change the schedule.
- **Encrypted storage:** Messages and files are encrypted at rest and in transit.
- **Multi-channel reminders:** Reminder channels include email, Signal, and Telegram.
- **Escalating grace periods:** Several reminder stages help prevent accidental triggering.
- **Unlimited trusted contacts:** The user can configure as many contacts as needed.
- **File attachments:** Intended for encrypted documents, passwords, recovery phrases, or other files.
- **Test mode:** Contacts can receive a test delivery before the switch is relied upon.
- **Privacy-first design:** The product is described publicly as not reading the user's messages or files.
- **Cancel anytime:** The product emphasizes no lock-in.

### Dead Man's Switch FAQ

#### What happens if I miss a check-in?

You get reminders on every channel you configured. Nothing is released until the full grace period passes with no response, which helps avoid false alarms when you are traveling, offline, or just busy.

#### Who should use a dead man's switch?

Anyone whose silence would create a real problem. Public examples include digital estate planning, crypto recovery, business continuity, private messages for family, and emergency instructions for trusted contacts.

#### What should I put in a dead man's switch?

Only information your contacts would actually need if you could not respond yourself. Public examples include:

- recovery instructions,
- where to find important documents,
- account handover steps,
- personal messages.

The product copy advises users to keep it focused and review it regularly.

#### Can I choose different contacts for different information?

Yes. The product page says users can add as many trusted contacts as they want, and each contact can receive different information.

#### Can my contacts see anything before the switch triggers?

No. Public copy says the user's messages stay encrypted and are only delivered after the switch triggers.

#### Can I change my check-in schedule?

Yes. Public copy says users can change check-in frequency, grace period, and contacts whenever they want.

#### How secure is my information?

The public answer is that information is encrypted at rest and in transit, the product is privacy-first, and the company does not read stored messages.

#### Can I test the system?

Yes. Public copy says users can send test deliveries to contacts before relying on the live switch.

#### How much does it cost?

Public product-page answer: **$5.99/month, $59/year, or $590 lifetime. Subscriptions can be paused or cancelled anytime.**

### Dead Man's Switch: Public Use Cases

The company's public educational copy presents these use cases:

- **Digital estate planning:** ensure family or executors can access what matters.
- **Family continuity:** if one person manages the passwords, bills, and account structure, pass on the map if they become incapacitated (see [use case page](https://alcazarsec.com/deadmanswitch/use-cases/families)).
- **Crypto recovery:** pass on recovery instructions or locations of seed material.
- **Business continuity:** if one person runs the accounts, approvals, passwords, or digital operations, pass on the map so customers stay protected and the business can keep operating (see [use case page](https://alcazarsec.com/deadmanswitch/use-cases/businesses)).
- **Private family messages:** leave letters, personal notes, or recordings for loved ones.
- **Emergency instructions:** give trusted contacts a plan to follow if the user disappears or becomes incapacitated.
- **Journalists, whistleblowers, and activists:** timed encrypted handoff to editors, counsel, or colleagues if check-ins stop; some users also discuss deterrence, which has real tradeoffs (see [use case page](https://alcazarsec.com/deadmanswitch/use-cases/journalists)).
- **Solo hikers, travelers, and adventurers:** release itineraries or coordinates if check-ins stop.
- **Public social legacy:** arrange for a final post, letter, or archive action after death or incapacity.

## Portable Secret: Expanded Context

### Plain-English Definition

Portable Secret is a browser-native way to create a self-decrypting encrypted HTML file. It is designed for sending or storing sensitive text and files without depending on accounts, portals, or custom software on the recipient side.

### Core Promise

Public copy repeatedly emphasizes:

- one file,
- no accounts,
- no server dependency for decryption,
- browser-native unlock,
- local encryption and local decryption,
- offline compatibility.

Representative public language:

- "Generate self-contained HTML files that decrypt locally in your browser."
- "The recipient must be able to decrypt the file with only a browser and a password."
- "No network calls occur. You can disconnect your internet and it still works."
- "No accounts, no servers, no dependencies."

### How Portable Secret Works

The public technical write-up describes the process as:

1. The user adds secret text and optional files.
2. The browser asks for a password.
3. A key is derived from the password.
4. The payload is encrypted.
5. The resulting file bundles encrypted data plus the code required to decrypt it later.
6. The recipient opens the file in a browser and enters the password.
7. The browser decrypts the content in memory.

Public technical notes:

- the encrypted payload is stored inside the generated HTML,
- AES-GCM is used for encryption,
- Argon2id is the preferred KDF,
- PBKDF2 is available as a compatibility fallback,
- calibration is used to estimate derivation cost and show realistic progress,
- a Web Worker is used when possible to keep the UI responsive,
- the decryption template is lightweight and framework-free.

The technical blog also describes the file as containing:

- a metadata block,
- a base64-encoded payload.

### Portable Secret FAQ

#### What does this do?

It creates a Portable Secret: a self-contained HTML file that unlocks encrypted data when you enter the password.

The file bundles an encrypted payload and the JavaScript needed to decrypt it using the browser's Web Crypto APIs. It can be opened with any browser, even offline.

#### Is my password or data sent to a server?

No. Everything happens locally in the browser.

The decryption logic lives inside the file. When the password is entered, the browser derives a key and decrypts the data in memory. Public FAQ copy says nothing is uploaded or sent anywhere.

#### How should I open it safely?

Public guidance says to open it offline in a private window. It also says to treat the file like a program run locally, and for extra assurance to turn off wifi or data before entering the password.

#### What happens if I forget the password?

The data is unrecoverable.

Public FAQ copy explicitly says there is no "Forgot Password" flow and no master key.

#### What kind of data can be inside?

Text plus multiple file attachments.

Public examples include:

- notes,
- images,
- documents,
- archives,
- other files.

#### Will this work on my phone or tablet?

Yes, on most modern browsers.

Public FAQ mentions reasonably recent Safari, Chrome, Firefox, and Edge. It notes that saving decrypted files depends on the device's file handling.

#### Can I store this on cloud drives or a USB stick?

Yes, if the password is strong.

Public FAQ says the payload is encrypted at rest, so the file is safe to store in insecure locations so long as the password is strong.

#### How secure is the encryption?

Public FAQ answer:

- modern, standard cryptography,
- AES-GCM for payload encryption,
- Argon2id by default where available,
- PBKDF2 as a browser-native fallback,
- the file includes whichever KDF was chosen during creation.

#### How is this different from a password-protected ZIP?

Public answer:

- better compatibility,
- safer cryptographic defaults,
- only a browser is needed,
- many ZIP flows are weaker or more cumbersome,
- Portable Secret can display content directly after decrypting.

#### Will this still work in 10 or 20 years?

Public answer: very likely.

The rationale given publicly is that the file is plain HTML and JavaScript relying on web standards and the Web Crypto API.

#### Is this open source? Can I see the code?

Yes.

Public materials point to [github.com/alcazarsec/portable-secret](https://github.com/alcazarsec/portable-secret).

### Portable Secret: Public Use Cases

The company's public writing gives at least these use cases:

- **Insecure-channel handoff:** send a contract, tax form, or sensitive document over email, then deliver the password by another channel.
- **Digital emergency kit:** store a password, recovery phrase, emergency contact list, or key instructions on a USB drive or in a safe place.
- **Dead Man's Switch payload:** attach a Portable Secret to a Dead Man's Switch so the service handles timing but not the raw secret.
- **Client credential handoff:** send credentials without leaving them in Slack, Teams, or searchable chat history.

Portable Secret is also positioned as useful when:
