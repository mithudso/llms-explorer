## How it works

- [statement] Dedicated Search Nodes do not make Atlas Search synchronously consistent with database writes. MongoDB's Erik Hatcher describes eventual-consistency lag as dependent on workload, architecture and resource contention; his design-review example used a separate cache when lag did not meet the application's requirement. (low confidence) — https://dev.to/erikhatcher/when-not-to-use-atlas-search-kh9
- [statement] MongoDB documents a minimum of two dedicated Search Nodes, billed hourly per node. Atlas bills partial hours as full hours, starts charging when the configuration is created, and bills both instance sizes for the first hour after a search-tier change. (low confidence) (verified as of 2026-10-31) — https://www.mongodb.com/docs/atlas/billing/search-node.md

## Measurements and reference values

- [statement] Dedicated Search Nodes deploy per shard: MongoDB's example assigns six Search Nodes when two are configured for each of three shards. For a single-region configuration with uniform hourly node price p and S shards, the documented minimum implies search compute of 2 × S × p per billed hour, before database and network charges; this is a derived formula, not a vendor dollar quote. ## Problems, failure modes and limitations

- [statement] Co-located search has availability exposure during cluster changes: MongoDB documents cases where mongod is available before mongot and search queries fail. An October 12, 2026 user test reported 55 final HTTP 503 responses during a scale-down despite retries across three members; that observation is one deployment, not a fleet-wide failure rate. (medium confidence) — https://www.mongodb.com/docs/search/deployment/deployment-options.md · keywords: Atlas Search Nodes cost floor and co-located versus dedicated search · also: https://www.reddit.com/r/MongoDB_Official/comments/1x3wh0q/recurring_atlas_search_interruptions_during_both/

## Comparisons and alternatives

- [statement] Atlas bills a full hour even for partial-hour Search Node use. On an instance-size change, it charges for both old and new instances for the first hour, then only the new instance. Replacement of an unhealthy node is charged as one node rather than two. (low confidence) (verified as of 2026-10-31) — https://www.mongodb.com/docs/atlas/billing/search-node.md
- [statement] Dedicated Search Node costs include node count, search tier and traffic between Search Nodes and database nodes. Network-transfer charges appear at cluster level rather than as a separate Search Node network line, so a TCO model must include them. (high confidence) (verified as of 2026-10-31) — https://www.mongodb.com/docs/atlas/billing/search-node.md · keywords: Atlas Search Nodes cost floor and co-located versus dedicated search · also: https://www.mongodb.com/docs/search/deployment/deployment-options.md
- [statement] MongoDB recommends dedicated Search Nodes for production; this is deployment guidance rather than proof that co-located search is unavailable. Its co-location guidance warns that contention can impair indexing and query latency, while Tidewave independently describes the same resource-sharing trade-off. (medium confidence) (verified as of 2026-10-31) — https://www.mongodb.com/docs/search/deployment/deployment-options.md · keywords: Atlas Search Nodes cost floor and co-located versus dedicated search · also: https://tidewave.net/blog/atlas-search-adding-full-text-search-to-your-app-without-elasticsearch
