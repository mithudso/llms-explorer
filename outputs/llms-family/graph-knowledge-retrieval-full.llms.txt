## Complete Evidence Corpus

### Labeled Property Graph vs RDF Triplestore Storage Models

- **Fact**: Labeled Property Graphs store attributes directly on nodes and edges with pointer-based index-free adjacency, allowing O(1) traversal per hop without index scans, whereas traditional RDF stores decompose data into Subject-Predicate-Object triples requiring multi-way index joins.
  - *Source*: https://neo4j.com/docs/getting-started/appendix/graph-db-vs-rdbms/
  - *Also*: https://www.w3.org/TR/rdf11-concepts/
  - *Evidence*: ev:lpg_index_free_adj_01, ev:rdf_triple_indexing_01

- **Fact**: RDF engines enforce formal semantics via OWL ontologies and SHACL constraints, providing automated deductive reasoning and global URI disambiguation that standard property graph schemas lack without external validation layers.
  - *Source*: https://www.w3.org/TR/owl2-overview/
  - *Also*: https://www.w3.org/TR/shacl/
  - *Evidence*: ev:owl2_semantics_01, ev:shacl_constraints_01

- **Fact**: For variable-length path traversal (k > 3), property graphs with index-free adjacency exhibit sub-linear latency growth relative to total graph size, while triple stores encounter combinatorial join-state growth unless path queries are pre-indexed or translated into transitive reachability indices.
  - *Source*: https://ldbcouncil.org/benchmarks/snb/
  - *Also*: https://kuzudb.com/blog/what-every-gdbms-should-do-and-vision/
  - *Evidence*: ev:ldbc_snb_traversal_01, ev:kuzu_factorized_eval_01

### Graph Indexing and Adjacency Traversal Engines

- **Fact**: Compressed Sparse Row (CSR) and Compressed Sparse Column (CSC) formats provide static contiguous memory layouts with O(1) neighbor lookups and optimal cache-locality for analytical traversals, but require O(V+E) rebuilding overhead on dynamic graph updates.
  - *Source*: https://epubs.siam.org/doi/10.1137/1.9781611972887.ch2
  - *Also*: https://dl.acm.org/doi/10.1145/3318464.3389725
  - *Evidence*: ev:siam_csr_locality_01, ev:sigmod_graph_storage_01

- **Fact**: Dynamic graph engines utilize chunked adjacency lists, differential updates, or LSM-tree-backed key-value stores (e.g. RocksDB in Memgraph and NebulaGraph) to balance write amplification with neighbor iteration throughput.
  - *Source*: https://memgraph.com/docs/internals/storage-memory
  - *Also*: https://docs.nebula-graph.io/master/1.introduction/3.architecture/
  - *Evidence*: ev:memgraph_memory_storage_01, ev:nebulagraph_lsm_storage_01

- **Fact**: Vector-graph hybrid indexes integrate vector quantization (e.g. HNSW, IVF-PQ) into graph node storage, allowing simultaneous euclidean/cosine vector similarity filtering and topological neighbor expansion in a single scan.
  - *Source*: https://arxiv.org/abs/1603.09320
  - *Also*: https://neo4j.com/docs/cypher-manual/current/indexes/vector-indexes/
  - *Evidence*: ev:hnsw_malkov_01, ev:neo4j_vector_index_01

### Graph Community Detection Algorithms for RAG

- **Fact**: The Leiden algorithm resolves Louvain's fundamental defect of producing disconnected or weakly connected communities by introducing an explicit sub-community refinement step that guarantees partition connectivity.
  - *Source*: https://www.nature.com/articles/s41598-019-41695-z
  - *Also*: https://leidenalg.readthedocs.io/en/stable/
  - *Evidence*: ev:leiden_nature_traag_01, ev:leidenalg_docs_refinement_01

- **Fact**: Hierarchical community detection partitions large knowledge graphs into multi-scale clusters (from fine-grained sub-communities C3 to macro-thematic clusters C0), establishing the structured partition hierarchy required for multi-level GraphRAG summarization.
  - *Source*: https://arxiv.org/abs/2404.16130
  - *Also*: https://www.pnas.org/doi/10.1073/pnas.0706851105
  - *Evidence*: ev:edge_graphrag_hierarchies_01, ev:infomap_pnas_rosvall_01

- **Fact**: Modularity optimization (Newman-Girvan modularity Q) exhibits a resolution limit where communities smaller than sqrt(2L) cannot be resolved, necessitating Constant Potts Model (CPM) or resolution parameter tuning in RAG pipelines.
  - *Source*: https://www.pnas.org/doi/10.1073/pnas.0605965104
  - *Also*: https://arxiv.org/abs/1104.3083
  - *Evidence*: ev:fortunato_resolution_limit_01, ev:traag_cpm_resolution_01

  - *Also*: https://microsoft.github.io/graphrag/

- **Fact**: Root-level community summaries (C0) compress source text by approximately 97% while maintaining superior comprehensiveness (72% win rate) over baseline semantic search on corpus-spanning sensemaking queries.

  - *Also*: https://github.com/microsoft/graphrag

### Bitemporal Knowledge Graphs and Entity Resolution

- **Fact**: Bitemporal knowledge representations maintain two orthogonal temporal dimensions—valid time (when a relationship held in the real world) and transaction/system time (when the fact was recorded), enabling deterministic point-in-time state reconstruction and auditing.
  - *Source*: https://www.sigmod.org/publications/dblp/db/conf/vldb/Snodgrass95
  - *Also*: https://www.iso.org/standard/53681.html
  - *Evidence*: ev:snodgrass_tsql2_01, ev:iso_sql_temporal_01

- **Fact**: Probabilistic entity resolution under the Fellegi-Sunter methodology assigns log-likelihood ratio weights across blocking keys to link multi-source entity mentions with bounded false-positive merge rates.
  - *Source*: https://www.jstor.org/stable/2286061
  - *Also*: https://dl.acm.org/doi/10.1145/3318464.3389700
  - *Evidence*: ev:fellegi_sunter_jasa_01, ev:christen_record_linkage_01

- **Fact**: Deep learning entity resolution (cross-encoder bi-encoders and LLM tie-breakers) achieves F1-scores > 0.90 on benchmark datasets (e.g. DBLP-ACM, Amazon-Google), but requires canopy blocking to avoid O(N^2) pairwise comparisons.
  - *Source*: https://arxiv.org/abs/2004.00584
  - *Also*: https://arxiv.org/abs/2305.03495
  - *Evidence*: ev:li_deep_matcher_vldb_01, ev:peeters_llm_er_emnlp_01

### Hybrid Dense, Sparse, and Graph Retrieval Fusion

- **Fact**: Reciprocal Rank Fusion (RRF) with smoothing parameter k=60 achieves scale-invariant rank aggregation across unbounded BM25 lexical scores, dense vector cosine similarities, and graph traversal distance metrics without parameter tuning.
  - *Source*: https://dl.acm.org/doi/10.1145/1571941.1572114
  - *Also*: https://arxiv.org/abs/2210.11934
  - *Evidence*: ev:cormack_sigir_rrf_01, ev:beir_benchmark_fusion_01

- **Fact**: Three-way hybrid fusion (sparse lexical BM25 + dense embedding + topological graph PPR) achieves higher Mean Reciprocal Rank (MRR@10) and NDCG@10 than any pairwise combination on heterogeneous technical corpora.
  - *Source*: https://arxiv.org/abs/2404.16130
  - *Also*: https://arxiv.org/abs/2308.07107
  - *Evidence*: ev:graphrag_hybrid_eval_01, ev:enterprise_hybrid_benchmark_01

- **Fact**: Rank calibration via min-max normalization or z-score standardization before linear combination requires manual tuning per dataset distribution, whereas RRF provides distribution-free robustness across drifting corpus sizes.
  - *Source*: https://dl.acm.org/doi/10.1145/1571941.1572114
  - *Also*: https://link.springer.com/chapter/10.1007/978-3-030-45442-5_4
  - *Evidence*: ev:cormack_distribution_free_01, ev:springer_multimodal_norm_01
