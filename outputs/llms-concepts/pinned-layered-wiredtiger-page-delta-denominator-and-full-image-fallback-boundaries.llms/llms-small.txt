## How it works

- [statement] For a built, nonempty candidate, the first size check rejects when the integer quotient `r->delta.size * 100 / delta_base_size` is greater than `conn->page_delta.delta_pct`. If that check passes and the target flag is set, a second check rejects when `r->delta.size * 100 / chunk->image.size` is greater than `(100 + conn->page_delta.delta_pct) / 2`. Both divisions use integer arithmetic, so equality of a computed integer quotient to its bound passes that check; these are not exact real-valued percentage cutoffs. The image-denominator mode does not run the second check. Each size rejection increments `rec_page_delta_rejected_size_threshold` and clears `build_delta`. The extra image-relative check can reject a near-image delta even when the larger target denominator admits it.
