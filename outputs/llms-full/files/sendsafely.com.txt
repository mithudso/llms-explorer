## How SendSafely Works

SendSafely uses a split-key encryption architecture built on the OpenPGP message format (RFC 4880) with AES-256 symmetric encryption.

### Split-Key Architecture

The encryption key is split into two independent components:

1. **Client Secret** -- A 256-bit random value generated locally in the sender's browser. It is embedded in the URL fragment identifier of the secure sharing link (the part after the `#`). Per the HTTP specification, URL fragments are never sent to the server. SendSafely never sees this value.

2. **Server Secret** -- A 256-bit random value generated and stored by SendSafely's servers. It is delivered to the recipient only after successful identity verification.

3. **Key Derivation** -- The final AES-256 encryption key is derived by combining both secrets (forming a 512-bit passphrase) using the OpenPGP Iterated and Salted S2K method. This derivation happens entirely in the recipient's browser.

### Encryption Flow

**Sending:**
1. Sender uploads files. An encryption key is created from the Client Secret and Server Secret.
2. Files are encrypted client-side in the browser before being uploaded to SendSafely servers.
3. Sender shares a secure link. The Client Secret is embedded in the URL anchor and never disclosed to the server.

**Receiving:**
1. Recipient clicks the link and verifies identity via one-time passcode (email or SMS).
2. Browser receives the Server Secret and the encrypted file from SendSafely.
3. Browser reconstructs the full 512-bit passphrase from the Client Secret (in the URL) and Server Secret, derives the AES-256 key, and decrypts the file locally.

SendSafely stores only ciphertext. Even if subpoenaed, breached, or compromised, SendSafely cannot decrypt customer data because it never holds the Client Secret.

### Trusted Device Keys

When a user designates a browser as trusted, the browser generates a 2048-bit RSA key pair:

- **Private key** -- Stored only in the browser's HTML5 Local Storage, encrypted with a 128-bit AES key unique to the user account.
- **Public key** -- Uploaded to SendSafely servers.

When items are sent to a user with trusted browsers, the sender's machine retrieves the recipient's public key, encrypts a copy of the Client Secret with it, and uploads the encrypted copy. Only the private key in the recipient's browser can decrypt it.

### Transport Security

- All communications use HTTPS/TLS with HTTP Strict Transport Security (HSTS)
- A+ rating from SSL Labs
- Content Security Policy (CSP) headers restrict approved code sources and block XSS

### What SendSafely Can and Cannot See

**SendSafely CAN see (non-encrypted metadata):** Email addresses, phone numbers, file names, file sizes, login timestamps, IP addresses, browser version, OS type.

**SendSafely CANNOT see:** File contents, message contents, the full decryption key (only holds the Server Secret; Client Secret never reaches servers).

## Products

### Send & Receive

Encrypted file exchange accessible via web app, Outlook, or Gmail. Recipients open with one click -- no account needed.

**Key capabilities:**
- Files up to 100GB with no file type restrictions
- Each user gets a personal URL anyone can use to send them files securely
- Recipients can reply back with files to any item sent via SendSafely
- Works entirely through web browsers -- no software installation needed
- Access tracking with geographic location data and read notifications
- Revoke access at any time or add new recipients after sending
- Automatic file expiration and deletion with audit trail preservation
- SMS verification with one-time passcodes for recipient authentication
- Restrict file save and print for PDFs and images
- Document watermarking with recipient email overlay
- Full audit logging with SIEM integration capability

**Email integrations:**
- **Outlook plug-in** for encrypted file and message sending directly from Outlook and Office 365
- **Chrome extension** for Gmail with in-compose encryption and files up to 10GB
- **Serverless Email Gateway (SEG)** on AWS Lambda for automatic inbound and outbound email encryption based on policies; supports Office 365, G-Suite, Salesforce, Zendesk, and Freshdesk. Enterprise plan only.

### Dropzones

Embeddable upload widget for collecting encrypted files from anyone. One script tag on any page, portal, or helpdesk.

**Key capabilities:**
- White-label branding with custom logo and color scheme
- Mobile-ready with smartphone camera upload support
- Turn-key setup requiring no coding or technical knowledge
- Configurable access controls and file type blocking
- Embedded PDF and image viewer (no local saves needed)
- Pre-built connectors for Zendesk, Salesforce, Intercom, Freshdesk, and Jira
- Zapier integration connecting to 8,000+ platforms
- Native integration with Marketo, Pardot, and Unbounce
- REST API with SDKs for custom implementations

**Deployment options:**
- Hosted Dropzone page (no coding required)
- Embeddable JavaScript widget (single script tag)
- Dropzone Connector for automatic ticket/case linking

### Workspaces

Persistent encrypted storage for team collaboration on sensitive files. An encrypted alternative to ShareFile, SharePoint, Box, and Dropbox.

**Key capabilities:**
- Folder and subfolder organization with version history
- Three access levels: Viewer (download only), Contributor (create/update), Admin (manage collaborators)
- Granular folder-level permissions -- assign collaborators to specific folders only
- Activity monitoring with real-time notifications and exportable logs
- Restrict file save and print; document watermarking
- File size: Team and Business plans up to 2GB per file (removable via custom AWS S3); Enterprise up to 100GB per file

### Actions

Low-code/no-code automation engine for encrypted workflows, triggered by events in SendSafely. **Enterprise plan only.**

**Trigger events:**
- A secure package is finalized (Send Item or Dropzone upload)
- A file is uploaded to a Workspace

**Native actions (operate on metadata only, within SendSafely):**
- Block/Unblock files (quarantine)
- Hold/Release files (prevent deletion while allowing viewing)
- Delete file or package

**External actions (third-party via webhooks, can decrypt with API credentials):**
- CrowdStrike AV scanning (Falcon API)
- OPSWAT AV scanning (Metadefender API)
- Sophos AV scanning (SophosLabs Intelix API)
- S3 export for compliance archiving (WORM bucket support)
- Google Cloud DLP scanning for sensitive data detection
- Tines integration for security workflow orchestration

**Filters** enable granular control: limit workflows to specific Dropzones, Workspaces, user types, or based on prior action results (e.g., delete only if AV scan fails).

Actions are configured via a point-and-click workflow editor. External actions deploy within the customer's AWS environment. Enterprise customers can customize templates or use SendSafely Advisory Services for custom development.

### HALO

Secure data exchange for AI-powered customer service. HALO enables AI agents and support teams to securely collect sensitive files directly within customer conversations.

**HALO is not an AI product.** It is a security layer. It never performs AI inference, training, or processing.

**Three components:**

1. **Halo Send** -- On-page secure upload modal that appears inside the chat window. Supports drag-and-drop, files up to 100GB, encrypts client-side before data leaves the user's device.

2. **Halo Bridge** -- Platform-agnostic connectors with standardized APIs for handoffs between AI and human support systems.

3. **Halo Native** -- Deep integrations built specifically for Zendesk and Intercom that feel like part of the existing interface.

**How it works:**
1. AI agent recognizes a customer needs to upload a file and prompts them.
2. A secure modal opens in-chat. Files are encrypted client-side in the customer's browser before upload.
3. A secure SendSafely link is automatically posted back into the chat transcript. Human agents access files from their ticketing platform with SendSafely-controlled permissions.

**By default, the AI agent collects files but cannot access them.** Only when the conversation is handed off to a human agent or authorized backend system can files be accessed. Protected data never touches inference engines, chatbot logs, or training data.

**Supported AI platforms:** Ada, Zendesk AI, Intercom Fin, Salesforce Agentforce, Forethought, Amazon Connect.

**Use cases:** KYC and identity verification, financial services onboarding, HIPAA-compliant healthcare documentation, bug reports and troubleshooting.

**Awards:** Named finalist for Best Secure Messaging Solution in the 2026 SC Awards.

**Available on SendSafely Enterprise plan.**

**Coming soon.** Model Context Protocol server for AI agents. Will enable LLM-based agents (Claude, GPT) to interact with SendSafely programmatically for secure file operations within agentic workflows.

## Developer Resources

### REST API

Full REST API for programmatic access to all SendSafely capabilities.

- **Base URL:** `https://{portal}.sendsafely.com/api/v2.0/`
- **Authentication:** Every request requires `ss-api-key` header, `ss-request-timestamp` header, and HMAC-SHA256 request signature
- **Pagination:** Uses `pageSize` (1-100) and `rowIndex` parameters
- **Plan requirement:** API access requires Pro plan or above; Audit Log API requires Enterprise

**Core endpoint groups:**
- Packages: create, get, update, finalize, delete, search
- Recipients: add (single/batch), remove, get info, add phone number
- Files: get upload URLs, upload (direct to S3), download, delete
- Directories (Workspaces): create, delete, rename, move, list contents
- Messages: encrypt/upload, decrypt/download
- Contact Groups: create, delete, list, manage members
- Dropzone: add/remove/get recipients
- Audit Log: query events (PACKAGE_EVENT, ADMIN_EVENT, USER_EVENT) with 90-day retention
- Keys: generate API key, generate key pair, get keycode
