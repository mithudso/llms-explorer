# AgentSphere

> AgentSphere | Secure Code Sandbox Platform for AI Agents  
> Provides isolated cloud sandbox environments for safely executing AI-generated code  
> Cold start in ~100ms; assign one sandbox per agent/user/session

---
---

## Welcome to AgentSphere Docs

AgentSphere is a secure runtime infrastructure designed to execute AI-generated code inside isolated cloud sandboxes. With built-in support for Python and JavaScript/TypeScript SDK, developers can easily launch and manage sandbox environments programmatically.

Typical use cases of AgentSphere include AI-powered data analysis and visualization, executing AI-generated code across multiple languages, testing and evaluating code generation models, and serving as a runtime for agent-based applications or full AI-generated apps like Fragments.

Each agentsphere sandbox functions as a lightweight, isolated virtual machine — think of it as a dedicated computer for your AI model. With startup times as low as 150 milliseconds, you can launch multiple sandboxes in parallel, assigning one per AI agent, LLM session, or user interaction. For instance, in an AI-driven data analytics chatbot, a new sandbox could be spun up for every individual user session to ensure secure and consistent execution.

The AgentSphere SDK provides official Python and JavaScript/TypeScript interfaces for interacting with AgentSphere, enabling you to programmatically manage development environments and execute code.

This section walks you through how to start your first agentsphere sandbox and run your code in it.

## 1. Set Up Environment Variables

1. [Sign up](https://www.agentsphere.run/) and navigate to the [AgentSphere API Key](https://www.agentsphere.run/apikey) page.

2. Click the **CREATE KEY** button to create a new API key.

3. Add the API key into your `.env` file by setting the `AGENTSPHERE_API_KEY` environment variable.

  ```bash
export AGENTSPHERE_DOMAIN='agentsphere.run'
export AGENTSPHERE_API_KEY='your-api-key'

  ```

**Tip:**
    Replace `your-api-key` with your [AgentSphere API Key](https://www.agentsphere.run/apikey).

## 2. Install AgentSphere SDK

The Python and JavaScript/TypeScript SDK provides a robust interface for programmatically interacting with agentsphere sandboxes.

Install the AgentSphere SDK to your project by running the following command in your terminal.

<Tabs>
  <TabPanel label="Python">

  ```bash
pip install agentsphere python-dotenv
  ```
  
  **Tip:**
  For macOS, use `pip3 install agentsphere python-dotenv` instead.
  python version >=3.9

  </TabPanel>
  <TabPanel label="JavaScript & TypeScript">

  ```bash
npm i agentsphere-js dotenv
  ```
  **Tip:** node version >= 18

  </TabPanel>
</Tabs>

## 3. Run Your Code in AgentSphere Sandbox

1. Save the following code in the `main.py` file or the `index.js` file for starting your agentsphere sandbox, executing the code inside it and listing all files inside the root directory.

<Tabs>
  <TabPanel label="Python">

  ```python
from dotenv import load_dotenv
load_dotenv()
from agentsphere import Sandbox

sbx = Sandbox() # By default the sandbox is alive for 5 minutes
execution = sbx.run_code("print('hello world')") # Execute Python inside the sandbox
print(execution.logs)

files = sbx.files.list("/")
print(files)
  ```
  </TabPanel>
  <TabPanel label="JavaScript & TypeScript">

  ```javascript
const { Sandbox } = require('agentsphere-js');
const dotenv = require('dotenv')
dotenv.config();

async function main() {
    const sbx = await Sandbox.create() 
    const execution = await sbx.runCode('print("hello world")') // Execute Python inside the sandbox
    console.log(execution.logs)

    const files = await sbx.files.list('/')
    console.log(files)
}
main()
  ```
  </TabPanel>
</Tabs>

2. Run the above code with the following command:

<Tabs>
  <TabPanel label="Python">

  ```bash
python main.py
  ```

  </TabPanel>
  <TabPanel label="JavaScript & TypeScript">

  ```bash
node ./index.js 
  ```

## AgentSphere Desktop

AgentSphere Desktop is a secure virtual desktop ready for Computer Use. Each sandbox is isolated from the others and can be customized with any dependencies you need.

![AgentSphere Desktop](/docs/images/agentsphereDesktop.png)


## Get Started

AgentSphere Desktop is built on top of [AgentSphere Sandbox](https://www.agentsphere.run/).

1. Sign up at [AgentSphere](https://www.agentsphere.run) and get your API key.

2. Set environment variable `AGENTSPHERE_API_KEY` with your API key.

  </TabPanel>

### 3. Create Your Desktop

<Tabs>
  <TabPanel label="Python">

```python
from agentsphere_desktop import Sandbox

# Create a new desktop sandbox
desktop = Sandbox()

# Launch an application
desktop.launch('google-chrome')  # or vscode, firefox, etc.

# Wait 10s for the application to open
desktop.wait(10000)

# Stream the application's window
# Note: There can be only one stream at a time
# You need to stop the current stream before streaming another application
desktop.stream.start(
    window_id=desktop.get_current_window_id(), # if not provided the whole desktop will be streamed
    require_auth=True
)

# Get the stream auth key
auth_key = desktop.stream.get_auth_key()

# Print the stream URL
print('Stream URL:', desktop.stream.get_url(auth_key=auth_key))

# Kill the sandbox after the tasks are finished
# desktop.kill()
```

  </TabPanel>
  <TabPanel label="JavaScript & TypeScript">

```javascript
import { Sandbox } from 'agentsphere-desktop'

// Start a new desktop sandbox
const desktop = await Sandbox.create()

// Launch an application
await desktop.launch('google-chrome') // or vscode, firefox, etc.

// Wait 10s for the application to open
await desktop.wait(10000)

// Stream the application's window
// Note: There can be only one stream at a time
// You need to stop the current stream before streaming another application
await desktop.stream.start({
  windowId: await desktop.getCurrentWindowId(), // if not provided the whole desktop will be streamed
  requireAuth: true,
})

// Get the stream auth key
const authKey = desktop.stream.getAuthKey()

// Print the stream URL
console.log('Stream URL:', desktop.stream.getUrl({ authKey }))

// Kill the sandbox after the tasks are finished
// await desktop.kill()
```

  </TabPanel>
</Tabs>

Model Context Protocol (MCP) is an open standard that enables frontier LLMs to produce more relevant responses by safely interacting with external tools and resources where data lives. For more details, go to [MCP Concepts](https://modelcontextprotocol.io/quickstart/server#core-mcp-concepts).

## Overview

AgentSphere provides an official MCP server that you can use in your MCP client.

### Tools

**Sandbox Management**

| Tool Name | Description | Parameters | Result Description |
|-----------|-------------|------------|-------------------|
| sandbox_create | Create a new sandbox instance | - `template` (string, optional): Sandbox template name, defaults to "agentsphere-code-interpreter-v1"<br>- `timeout` (int, optional): Timeout in seconds, defaults to 43200 (12 hours)<br>- `metadata` (object, optional): Custom metadata<br>- `envs` (object, optional): Environment variables | Object containing sandbox_id, template, envd_version, etc. |
| sandbox_is_running | Check if sandbox is running | - `sandbox_id` (string): Unique sandbox identifier | Boolean: true if running, false if not |
| sandbox_settimeout | Dynamically adjust sandbox lifetime/expiration timeout | - `timeout` (int): Timeout duration in seconds<br>- `sandbox_id` (string, optional): Sandbox ID | Object containing sandbox_id, timeout, timestamp, etc. |
| sandbox_get_logs | Get sandbox logs | - `start` (int, optional): Starting position, defaults to 0<br>- `limit` (int, optional): Maximum log entries, defaults to 1000<br>- `sandbox_id` (string, optional): Sandbox ID | Object containing logs list, total count, has_more flag, etc. |

**Command Execution Tools**

| Tool Name | Description | Parameters | Result Description |
|-----------|-------------|------------|-------------------|
| exec_command | Execute Linux commands in sandbox | - `cmd` (string): Command to execute<br>- `sandbox_id` (string, optional): Sandbox ID | Object containing stdout, stderr, and success status |

**Network Service Tools**

| Tool Name | Description | Parameters | Result Description |
|-----------|-------------|------------|-------------------|
| get_preview_link | Get access URL for services running in sandbox | - `port` (int): **Required**, service listening port number<br>- `sandbox_id` (string, optional): Target sandbox ID | Object containing the preview URL |

**Filesystem Tools**

| Tool Name | Description | Parameters | Result Description |
|-----------|-------------|------------|-------------------|
| file_read | Read file content from sandbox | - `path` (string): File path in sandbox (e.g., "/home/user/test.txt")<br>- `sandbox_id` (string, optional): Sandbox ID | File content as string, empty string if file doesn't exist |
| sandbox_file_write | Write content to file in sandbox | - `path` (string): File path<br>- `content` (string): Content to write<br>- `sandbox_id` (string, optional): Sandbox ID | Object containing path, name, type, etc. |
| sandbox_mkdir | Create directory in sandbox | - `path` (string): Directory path (e.g., "/home/user/my/nested/dir")<br>- `sandbox_id` (string, optional): Sandbox ID | Object containing path, created status, etc. |
| sandbox_list_dir | List entries in directory | - `path` (string): Directory path to list<br>- `sandbox_id` (string, optional): Sandbox ID | Object containing entries list, file/directory counts, etc. |
| sandbox_dir_exist | Check if file or directory exists | - `path` (string): Path to check<br>- `sandbox_id` (string, optional): Sandbox ID | Boolean: true if exists, false if not |
| upload_files_to_sandbox | Upload local files or folders to sandbox | - `local_path` (string): Local absolute path<br>- `target_path` (string, optional): Target path in sandbox, defaults to /user_uploaded_files/<br>- `sandbox_id` (string, optional): Sandbox ID | List of successfully uploaded files or error information |
| find_file_path | Search for absolute paths of files or directories by name | - `filename` (string): File name to search (supports wildcards like "*.py", "project*")<br>- `search_path` (string, optional): Search starting path or shortcut ("desktop", "documents", "downloads", "home"), defaults to desktop | List of found files/directories with complete path, type, size, modification time, etc. |

**PTY Terminal Tools**

| Tool Name | Description | Parameters | Result Description |
|-----------|-------------|------------|-------------------|
| pty_create | Cross-platform terminal launch and agentsphere CLI command execution | - `sandbox_id` (string, optional): Sandbox ID | Object containing platform, process_id, command, etc. |
| pty_send_input | Send input command to PTY sandbox | - `input` (string): Input command content to send to sandbox<br>- `sandbox_id` (string, optional): Sandbox ID | Object containing sandbox_id, input, timestamp, etc. |
| pty_get_latest_output | Get latest output from sandbox PTY | - `sandbox_id` (string, optional): Sandbox ID<br>- `timeout` (float, optional): Timeout for waiting output response (seconds), defaults to 2.0 | Object containing output, has_output, timestamp, etc. |
| pty_kill | Close PTY connection and cleanup client | - `sandbox_id` (string): sandbox ID to kill | Object containing sandbox_id, timestamp, etc. |

## Install AgentSphere MCP Sever

### Get AgentSphere API Key

1. Visit [AgentSphere official website](https://www.agentsphere.run/).  

2. Create an account and log in.  

3. Go to the **API Keys** page and copy your **API key**.

### Install `uv`

AgentSphere MCP Server runs via `uv`, a modern, fast Python package & project manager.  

1. Open your **Terminal**.  

2. Install **Homebrew** if it has not been installed yet:

   ```bash
   /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
   ```

3. Install `uv` using `Homebrew`:

	```bash
	brew install uv
	```

### Add to Claude Code

1. Run the following command in your terminal to install AgentSphere MCP Server to your Claude Code.

```bash
claude mcp add agentsphere --scope user \
  --env AGENTSPHERE_API_KEY="your_api_key_here" \
  -- uvx agentsphere-mcp-server@latest
```

**Note:** 

- Replace `your_api_key_here` with your actual AgentSphere API key.

- Using `--scope user` means the AgentSphere MCP Server is available to you across all projects. To share with others in a project, use `--scope project`. For more information, see [Anthropic Documentation](https://docs.anthropic.com/en/docs/claude-code/mcp).


2. To verify the installation, run the following command in your terminal:

```bash
claude mcp list
```

**Expected output:**

```bash
Checking MCP server health...
agentsphere: uvx agentsphere-mcp-server - ✓ Connected
```

## Template Management

### Build Template

Build a sandbox template (requires Docker to be installed first):

```bash
agentsphere template build [template] [options]
```

**Parameters:**
- `[template]`: Optional, specify the template ID to rebuild.

**Common Options:**
- `-p, --path <path>`: Specify a project root directory path.
- `-d, --dockerfile <file>`: Specify a Dockerfile path.
- `-n, --name <template-name>`: Specify a template name.
- `-c, --cmd <start-command>`: Specify a startup command.
- `--ready-cmd <ready-command>`: Specify a readiness check command.
- `--team <team-id>`: Specify a team ID.
- `--cpu-count <cpu-count>`: Specify a CPU core count (default: 2).
- `--memory-mb <memory-mb>`: Specify a memory size in MB (default: 512).
- `--build-arg <args...>`: Specify docker build arguments.
- `--no-cache`: Skip cache during build.

### Initialize Template

Create an `agentsphere.Dockerfile` file in your root directory:

```bash
agentsphere template init [options]
```

**Options:**
- `-p, --path <path>`: Specify project root directory path.

### View Template List

List all available templates:

```bash
agentsphere template list [options]
```

**Options:**
- `--team <team-id>`: Filter by team.

**Note:** Replace `<team-id>` with the actual team ID, which can be obtained from **Dashboard > Team** page.

### Delete Template

Delete a specified template:

```bash
agentsphere template delete <template-id>
```

**Note:**

* Replace `<template-id>` with the actual template ID. You can get it from **Dashboard > Templates** page.

* Public templates cannot be deleted.

### Publish Template

Publish a specified template to the public library:

```bash
agentsphere template publish <template-id>
```

**Note:** Replace `<template-id>` with the actual template ID. You can get it from **Dashboard > Templates** page.

### Unpublish Template

Unpublish a specified template from the public library:

```bash
agentsphere template unpublish <template-id>
```

**Note:** Replace `<template-id>` with the actual template ID. You can get it from **Dashboard > Templates** page.

## View Sandboxes

### List All Sandboxes

Run the following command to list all currently running sandbox instances:

```bash
agentsphere sandbox list
```

To filter sandboxes by their state, you can specify the `--state` option. Supported states include: `running`, `paused`, etc.

```bash
agentsphere sandbox list --state running
agentsphere sandbox list --state paused
agentsphere sandbox list --state running,paused  # Multi-state filtering
```

To filter sandboxes by their metadata, you can specify the `--metadata` option:

```bash

```

## Create Sandbox

Create a sandbox using a specified template and connect to the terminal:

```bash
agentsphere sandbox create <template-id/name>
```

**Note:**

* Replace `<template-id/name>` with the actual template ID or name. You can find this information in **Dashboard > Templates**.

* Created sandboxes have auto-pause functionality enabled by default, and will automatically pause instead of being destroyed after timeout. You can use the `--timeout` option to set the timeout in seconds, for example: `--timeout 3600` (1 hour).

## Create Temporary Sandbox

Create a temporary sandbox using a specified template and connect to the terminal:

```bash
agentsphere sandbox spawn <template-id/name>
```

**Note:**

* Replace `<template-id/name>` with the actual template ID or name. You can find this information in **Dashboard > Templates**.

* The temporary sandbox will be immediately destroyed after you exit the sandbox environment using the `exit` command.

```bash
agentsphere sandbox pause <sandbox-id>
```


## Resume Paused Sandboxes

Resume a specified sandbox (replace `<sandbox-id>` with the actual sandbox ID):

```bash
agentsphere sandbox resume <sandbox-id>
```

**Note:** Resumed sandboxes have auto-pause functionality enabled by default. You can use the `--timeout` option to set the timeout in seconds.

## Set Sandbox Time-to-Live

Set TTL for a specified sandbox (replace `<sandbox-id>` with the actual sandbox ID and `<timeout>` with seconds):

```bash
agentsphere sandbox ttl <sandbox-id> --timeout <timeout>
```

Set TTL for all running sandboxes:

```bash
agentsphere sandbox ttl --all --timeout <timeout>
```

**Note:** TTL is in seconds. Setting TTL will recalculate the sandbox's time-to-live from the current time, with a maximum limit of 12/24 hours (depending on your subscription plan).

```bash
agentsphere sandbox metrics sandbox-123 --follow

agentsphere sandbox metrics sandbox-123 --format json
```

```bash
agentsphere sandbox kill --all
```

To upload multiple files or a directory of files:

```python
import os
from agentsphere import Sandbox

sandbox = Sandbox()

def read_directory_files(directory_path):
    files = []
    
    # Iterate through all files in the directory
    for filename in os.listdir(directory_path):
        file_path = os.path.join(directory_path, filename)
        
        # Skip if it's a directory
        if os.path.isfile(file_path):
            # Read file contents in binary mode
            with open(file_path, "rb") as file:
                files.append({
                    'path': file_path,
                    'data': file.read()
                })
    
    return files

files = read_directory_files("/local/dir")
print(files)
# [
#  {"'path": "/local/dir/file1.txt", "data": "File 1 contents..." },
#   { "path": "/local/dir/file2.txt", "data": "File 2 contents..." },
```

```javascript
import fs from 'fs';
import path from 'path';

import { Sandbox } from 'agentsphere-js';

const sandbox = await Sandbox.create();

// Read all files in the directory and store their paths and contents in an array
const readDirectoryFiles = (directoryPath) => {
  // Read all files in the local directory
  const files = fs.readdirSync(directoryPath);

  // Map files to objects with path and data
  const filesArray = files
    .filter(file => {
      const fullPath = path.join(directoryPath, file);
      // Skip if it's a directory
      return fs.statSync(fullPath).isFile();
    })
    .map(file => {
      const filePath = path.join(directoryPath, file);

      // Read the content of each file
      return {
        path: `/sandbox-files/${file}`,
        data: fs.readFileSync(filePath, 'utf8')
      };
    });

  return filesArray;
};

// Usage example
const files = readDirectoryFiles('/local/dir');
console.log(files);
// [
//   { path: '/local/dir/file1.txt', data: 'File 1 contents...' },
//   { path: '/local/dir/file2.txt', data: 'File 2 contents...' },
```

## Watch a Directory

Since events are tracked asynchronously, their delivery might be delayed. To watch a directory for changes, you can use the `files.watch_dir()` method.

<Tabs>
  <TabPanel label="Python">

```python
from agentsphere import Sandbox
from agentsphere import FilesystemEventType

sandbox = Sandbox()
dirname = '/home/user'

# Watch directory for changes
handle = sandbox.files.watch_dir(dirname)

# Trigger file write event
sandbox.files.write(f"{dirname}/my-file", "hello")

# Retrieve the latest new events since the last `get_new_events()` call
events = handle.get_new_events() 
for event in events: 
  print(event) 
  if event.type == FilesystemEventType.WRITE: 
    print(f"wrote to file {event.name}") 
```

  </TabPanel>
  <TabPanel label="JavaScript & TypeScript">

  
```javascript
import { Sandbox, FilesystemEventType } from 'agentsphere-js'

const sandbox = await Sandbox.create()
const dirname = '/home/user'

// Start watching directory for changes
const handle = await sandbox.files.watchDir(dirname, async (event) => {
  console.log(event)
  if (event.type === FilesystemEventType.WRITE) {
    console.log(`wrote to file ${event.name}`)
  }
})

// Trigger file write event
await sandbox.files.write(`${dirname}/my-file`, 'hello')

```

  </TabPanel>
</Tabs>

**Tip:** It's recommended not to collect or shut down watcher immediately after making a change.

## Recursively Watch

To enable a recursive watch, you can add the `recursive` parameter so that you can watch all changes under a directory without setting up a watcher for each layer of folders.

<Tabs>
  <TabPanel label="Python">

```python
from agentsphere import Sandbox
from agentsphere import FilesystemEventType

sandbox = Sandbox()
dirname = '/home/user'

# Watch directory for changes
handle = sandbox.files.watch_dir(dirname, recursive=True)

# Trigger file write event
sandbox.files.write(f"{dirname}/my-folder/my-file", "hello")

# Retrieve the latest new events since the last `get_new_events()` call
events = handle.get_new_events()
for event in events:
  print(event)
  if event.type == FilesystemEventType.WRITE:
    print(f"wrote to file {event.name}")
```

  </TabPanel>
  <TabPanel label="JavaScript & TypeScript">
  
```javascript
import { Sandbox, FilesystemEventType } from 'agentsphere-js'

const sandbox = await Sandbox.create()
const dirname = '/home/user'

// Start watching directory for changes
const handle = await sandbox.files.watchDir(dirname, async (event) => {
  console.log(event)
  if (event.type === FilesystemEventType.WRITE) {
    console.log(`wrote to file ${event.name}`)
  }
}, {
  recursive: true
})

// Trigger file write event
await sandbox.files.write(`${dirname}/my-folder/my-file`, 'hello')

```

  </TabPanel>
</Tabs>

**Tip:** When new folders (for example, deeply nested path of folders) are rapidly created, events except for `CREATE` might not be captured. To avoid this, you can create the required folder structure in advance.

## Invalid API Key

**Symptom:** You receive the following 401 error message, "Invalid API key", when trying to create or interact with a sandbox.


## Sandbox Startup Issues

Occasionally, a sandbox may take a few seconds to fully initialize and open its communication ports after being created. If you attempt to execute code immediately, you may encounter a TimeoutException, because your code is trying to connect before the sandbox is ready.

**Symptom:**

```bash

You can modify the sandbox timeout by passing 'timeout' when starting the sandbox or calling '.set_timeout' on the sandbox with the desired timeout.
```

### Solution 2: Exponential Backoff

A more robust and efficient solution (recommended for production)​​ is to implement a waiting loop with exponential backoff. This strategy repeatedly checks if the sandbox is ready, increasing the wait time after each failed attempt. It adapts to varying startup times and avoids unnecessary delays.

<Tabs>
  <TabPanel label="Python">

  ```python
def wait_for_sandbox(sandbox, max_retries=5, initial_delay=1, backoff_factor=2):
    """
    Wait for sandbox to be ready
    :param sandbox: Sandbox instance
    :param max_retries: Maximum retry attempts
    :param initial_delay: Initial delay in seconds
    :param backoff_factor: Multiplier for delay after each failure
    :return: bool whether sandbox is ready
    """
    delay = initial_delay
    for attempt in range(max_retries):
        if sandbox.is_running():
            return True
        print(f"Sandbox not ready, waiting {delay:.2f} seconds (attempt {attempt + 1}/{max_retries})")
        time.sleep(delay)
        delay *= backoff_factor
    return False
  ```
  </TabPanel>
  <TabPanel label="JavaScript & TypeScript">

  ```javascript

dotenv.config();

async function waitForSandbox(sandbox, maxRetries = 5, initialDelay = 1000, backoffFactor = 2) {
  /**
   * Wait for sandbox to be ready
   * @param {Sandbox} sandbox - Sandbox instance
   * @param {number} maxRetries - Maximum retry attempts
   * @param {number} initialDelay - Initial delay in milliseconds
   * @param {number} backoffFactor - Multiplier for delay after each failure
   * @returns {Promise<boolean>} whether sandbox is ready
   */
  let delay = initialDelay;
  
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    if (await sandbox.isRunning()) {
      return true;
    }
    
    console.log(`Sandbox not ready, waiting ${delay/1000} seconds (attempt ${attempt + 1}/${maxRetries})`);
    await setTimeout(delay);
    delay *= backoffFactor;
  }
  
  return false;
}

async function smartWaitExample() {

    console.error("Error: Sandbox failed to start");
    return;
  }

  const execution = await sbx.runCode("console.log('hello world')");
  console.log(execution.logs);
}

smartWaitExample();
  ```

### Best Practices

* **Always Check Status:** In production code, always implement a waiting strategy before executing the first command in a new sandbox.

* **Prefer Exponential Backoff:** Use the exponential backoff method for reliability and efficiency over a fixed wait.

* **Set Appropriate Timeouts:** Remember to set an appropriate overall lifecycle timeout for the sandbox itself, distinct from the startup wait time.

* **Clean Up Resources:** Always shut down sandboxes when they are no longer needed to free up resources.



## Docker Push Authentication Error

When pushing Docker images to the registry, you may encounter authentication failures. This typically occurs when Docker fails to transmit credentials to the target registry.

**Root Cause**: The Docker daemon cannot authenticate with the local registry proxy, preventing successful image uploads.

**Solution**: Configure Docker to treat the local registry as an insecure registry, allowing the local proxy to handle authentication seamlessly.

### macOS

Follow these steps to configure Docker Desktop on macOS:

1. Launch Docker Desktop.
2. Navigate to **Settings**.
3. Select **Docker Engine**.
4. Add the insecure registry configuration to the JSON settings:

  ```json
  {
    "insecure-registries": ["host.docker.internal:49984"]
  }
  ```

  Your complete configuration might resemble the following example:

  ```json
  {
    "builder": {
      "gc": {
        "defaultKeepStorage": "20GB",
        "enabled": true
      }
    },
    "features": {
      "buildkit": true
    },
    "insecure-registries": [
      "host.docker.internal:49984"
    ]
  }
  ```

  This configuration enables Docker to route requests through the local proxy, which manages authentication automatically.

5. Click **Apply & Restart** to apply the changes.

### Linux

Configure the Docker daemon on Linux systems:

1. Edit the Docker daemon configuration file at `/etc/docker/daemon.json`. Create this file if it doesn't exist:

  ```json
  {
    "insecure-registries": ["localhost:49984"]
  }
  ```

2. Restart the Docker service to apply the configuration changes:

  ```bash
  sudo systemctl restart docker
  ```

### Windows

Configure Docker Desktop on Windows:

1. Open Docker Desktop.
2. Navigate to **Settings**.
3. Select **Docker Engine**.
4. Add the insecure registry configuration to the JSON settings:

  ```json
  {
    "insecure-registries": ["host.docker.internal:49984"]
  }
  ```

5. Click **Apply & Restart** to apply the changes.

### Mount the bucket

To mount Google Cloud Storage, install the `gcsfuse` package.

Here's a simple `Dockerfile` example:

```dockerfile
FROM ubuntu:latest

RUN apt-get update && apt-get install -y gnupg lsb-release wget
RUN lsb_release -c -s > /tmp/lsb_release

    echo "deb https://packages.cloud.google.com/apt gcsfuse-$GCSFUSE_REPO main" \

RUN wget -O - https://packages.cloud.google.com/apt/doc/apt-key.gpg | apt-key add -
```

## How It Works

Every time you build a sandbox template, AgentSphere creates a container based on the `agentsphere.Dockerfile` you provide, extracts the container's filesystem, performs provisioning and configuration (e.g., installing required dependencies), and starts a sandbox.

Then, these steps happen:

1. Take the running sandbox.

2. (Only if you specified the start command — otherwise this step is skipped) Execute the start command.

3. Wait for readiness (by default 20 seconds if a start command is specified, otherwise immediately ready). Readiness check can be configured using a ready command.

4. Snapshot the sandbox and make it ready to spawn with the SDK. This sandbox snapshot is also as known as a sandbox template.

**Sandbox Snapshot**

Snapshots are saved running sandboxes. AgentSphere serializes and saves the entire sandbox filesystem together with all the running processes in a way that can be reloaded later. This allows you to load the sandbox in just a few hundred milliseconds with all processes already running and the filesystem exactly as it was.


----------------------------------------
----------------------------------------

The **ready command** allows you to specify a command that determines when a template sandbox is ready before a snapshot is created. It is executed in an infinite loop until it returns a successful exit code `0`. This enables precise control over how long the system should wait for the start command or any other system state.

---

## Add a Ready Command

When building a sandbox template, you can specify the ready command using the `--ready-cmd` option:

```bash
agentsphere template build --ready-cmd "<your-ready-command>"
```

## Sandbox Template Config

You can also define the ready command inside the `agentsphere.toml` in the same directory where you run `agentsphere template build`:

```toml
# This is a config for AgentSphere sandbox template
template_id = "<your-template-id>"
dockerfile = "agentsphere.Dockerfile"
template_name = "<your-template-name>"
ready_cmd = "<your-ready-command>"
```

## Default Values

Without any given ready command, the default is set to `sleep 0`, meaning the sandbox template is immediately ready.

If a start command is defined, the default ready command is set to `sleep 20`, meaning the template sandbox will wait 20 seconds before taking the snapshot.

## Examples

**Wait for a URL to Return 200 Status Code**

```toml
ready_cmd = 'curl -s -o /dev/null -w "%{http_code}" http://localhost:3000 | grep -q "200"'
```

**Wait for a Specific Process to Start**

```toml
ready_cmd = 'pgrep my-process-name > /dev/null'
```

**Wait for a File to Exist**

```toml
ready_cmd = '[ -f /tmp/ready.flag ]'
```


----------------------------------------
----------------------------------------

The **start command** allows you to specify a command that will already be running when you spawn your custom sandbox. For example, you can have running servers or seeded databases inside the sandbox that are fully ready when you spawn the sandbox using the SDK — resulting in zero waiting time for your users during runtime.

The intention of the start command is to reduce wait times and ensure everything is prepared when you spawn your sandbox.

---

## Add a Start Command

When you are building a sandbox template, you can specify the start command by using the `-c` option:

```bash
agentsphere template build -c "<your-start-command>"
```

When you spawn the custom sandbox you built, the start command will already be running if there was no error during its execution.

**Sandbox Template Config**

You can also specify the start command inside the `agentsphere.toml` in the same directory where you run `agentsphere template build`:

```toml
# This is a config for AgentSphere sandbox template
template_id = "<your-template-id>"
dockerfile = "agentsphere.Dockerfile"
template_name = "<your-template-name>"
start_cmd = "<your-start-command>"
```

## Logs

You can retrieve the start command logs using the CLI:

```bash
agentsphere sandbox logs <sandbox-id>
```

You can fetch all pages by looping through the paginator while checking if there is a next page (using `hasNext` or `has_next` property) and fetching until there are no more pages left to fetch:

```python
from agentsphere import Sandbox, SandboxQuery

    sandboxes.extend(items)
```

## Pause and Resume Sandboxes

The sandbox persistence allows you to pause your sandbox and resume it later from the same state it was in when you paused it. During the pause period, your sandbox will not be charged.

## Pause Sandbox

When you pause a sandbox, both the sandbox's filesystem and memory state will be saved, including all the files in the sandbox's filesystem and all the running processes, loaded variables, data, etc.

<Tabs>
  <TabPanel label="Python">

```python
from agentsphere import Sandbox

sbx = Sandbox.create()
print('Sandbox created', sbx.sandbox_id)

# Pause the sandbox
# You can save the sandbox ID in your database to resume the sandbox later
sbx.beta_pause()
print('Sandbox paused', sbx.sandbox_id)
```

  </TabPanel>
  <TabPanel label="JavaScript & TypeScript">

```javascript
const { Sandbox } = require('agentsphere-js');
import 'dotenv/config'

async function main() {
  // Create a sandbox
  const sbx = await Sandbox.create();

  console.log('Sandbox created with ID:', sbx.sandboxId);

  // Pause the sandbox
  setTimeout(async () => {
      const sandboxId = await sbx.pause()
      console.log('Sandbox paused', sandboxId)
  }, 1000*20) // Pause the sandbox after a 20-second delay

}
main()
```

  </TabPanel>
</Tabs>


## Resume Sandbox

When you resume a sandbox, it will be in the same state as it was in when you paused it. All the files in the sandbox's filesystem and all the running processes, loaded variables, data, will be restored.

Note that if it exceeds the end time set when the sandbox was created, the sandbox cannot be resumed.

<Tabs>
  <TabPanel label="Python">

```python
from agentsphere import Sandbox

sbx = Sandbox.create()
print('Sandbox created', sbx.sandbox_id)

# Pause the sandbox
# You can save the sandbox ID in your database to resume the sandbox later
sbx.beta_pause()
print('Sandbox paused', sbx.sandbox_id)

# Connect to the sandbox (it will automatically resume the sandbox, if paused)
same_sbx = sbx.connect()
print('Connected to the sandbox', same_sbx.sandbox_id)
```

  </TabPanel>

## Remove paused sandboxes

You can remove paused sandboxes by calling the `kill` method on your sandbox instance.

<Tabs>
  <TabPanel label="Python">

```python
from agentsphere import Sandbox

sbx = Sandbox.create()

# Pause the sandbox
sbx.beta_pause()

sbx.kill()

Sandbox.kill(sbx.sandbox_id)
```

## Auto-pause (beta)

**Note:**
- Auto-pause is currently in beta and available through `Sandbox.betaCreate()`/`Sandbox.beta_create()` method.
- The auto-pause is **persistent**, meaning that if your sandbox resumes and it times out, it will be automatically paused again.
- The default inactivity timeout is 10 minutes. You can change the timeout by passing the timeoutMs/timeout parameter to the `Sandbox.connect()`/`Sandbox.connect()` method.
- If you shut down the sandbox using `.kill()`, it will be permanently deleted and you won't be able to resume it.

Sandboxes can now automatically pause after they time out. When a sandbox is paused, it stops consuming compute but preserves its state.

<Tabs>
  <TabPanel label="Python">

```python
from agentsphere import Sandbox

# Create sandbox with auto-pause enabled (Beta)
sandbox = Sandbox.beta_create(
    auto_pause=True  # Auto-pause after the sandbox times out
    timeout=10 * 60, # Optional: change the default timeout (10 minutes)
)
```

  </TabPanel>
  <TabPanel label="JavaScript & TypeScript">

```javascript
import { Sandbox } from 'agentsphere-js'
import 'dotenv/config'

// Create sandbox with auto-pause enabled (Beta)
const sandbox = await Sandbox.betaCreate({
    autoPause: true, // Auto-pause after the sandbox times out
    timeoutMs: 10 * 60 * 1000 // Optional: change the default timeout (10 minutes)
})
```

Metadata is a way to attach arbitrary key-value pairs for a sandbox, which can be used to:

- Associate a sandbox with a user session.
- Store custom user data for a sandbox like API keys.
- Associate a sandbox with a user ID and [connect](/docs/sandbox/connect) to it later.

## Specify Metadata

You can specify metadata when creating a sandbox and can access it later by listing running sandboxes with `Sandbox.list()` method.

<Tabs>
  <TabPanel label="Python">

```python
from agentsphere import Sandbox

# Create sandbox with metadata.
sandbox = Sandbox(
  metadata={
    'userId': '123', 
  },
)

# List running sandboxes and access metadata.
running_sandboxes = Sandbox.list()
# Will print:
# {
#   'userId': '123',
# }
print(running_sandboxes[0].metadata)
```
  </TabPanel>
  <TabPanel label="JavaScript & TypeScript">
  
```javascript

// {
//   'userId': '123',
```
