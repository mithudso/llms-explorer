# DR: named-topic research to an expert skill

Read [mongo-protocol.md](mongo-protocol.md) and [evidence.md](evidence.md).
Research the named topic within the commissioned scope. Family gap discovery
belongs to [cfe.md](cfe.md); repeated depth inside one concept belongs to
[rabbithole.md](rabbithole.md). MongoDB holds every durable input and output.

## Scope and depth

Default to `standard`. Respect explicit options and saved plans. A dependency
foundation is researched before its siblings. Reuse an exact prior concept or
spoke as a gap-focused refresh; do not start a duplicate full research run.
An orchestrator's bounded brief already supplies confirmed scope.

| Depth | Concepts per bounded DR run | Sources per concept | Pass contract |
| --- | --- | --- | --- |
| `quick` | At most 3 | At least 2 meaningful URLs plus domain authority | One pass; no saturation loop |
| `standard` | Target 5; at most 8 | At least 3 meaningful URLs plus domain authority | One research/scout pass; one negation round; conditional one follow-up |
| `saturate` | At most 15 per bounded run | At least 3 meaningful source URLs plus domain authority | Two independent passes per concept, then gap-focused rounds to two empty rounds with source floors met |

These are bounded research-run sizes, not a cap on an entire CFE family or queue.
Split larger authorized queues and process every subgroup unless the user sets
an explicit budget. Saturate reserves about 20% of queries for disconfirmation.

Codex research, scout, merge and scope-check default to `gpt-6.1-sol` at `medium`.
Claude research wrappers preserve their current Sonnet defaults. Preserve explicit
model/effort overrides and save actual enforced settings, rather than claiming
frontmatter switches an existing session. The trusted server's independent gate
uses its configured maintained judge. Do not choose a cheaper scout by assuming
an obsolete model mapping or capability.

## Execute

1. Inspect prior work and complete dedup. Record full question coverage, scope,
   ordered concepts, depth contract, models, budgets and plan in one owned run.
   For `--dry-run`, present these from read tools without saving or dispatching.
2. For each concept, state its authoritative source type, volatility and what
   would disconfirm the expected conclusion. Inspect shared source snapshots,
   qualified parent facts and relevant peer/scout seeds. Preserve provenance.
3. Dispatch bounded workers with exact concept, in/out scope, source seeds,
   domain/URL floors, question coverage and output schema. Workers return atomic
   structured claims and complete evidence, not free-form stitched prose. Save
   brief, worker response and attempt receipts in Mongo. Use at most four DR
   research workers in flight; nested CFE runs use its lower run concurrency.
4. In standard's first pass, deliberately search deeper primary material:
   postmortems, engineering blogs, issue trackers, forums, source code and papers.
   Record at least six searches and a scout report with tiers seen, candidate
   sources, unread evidence and stated information gaps. Follow citation chains
   to original sources. Include an independent negation round.
5. Run exactly one additional seeded standard pass if unread deeper evidence
   addresses a stated gap, domain/origin or source/unique-claim floors are missed,
   or the scout report is incomplete. The maintained adaptive probe uses eight
   normalized unique claims as its follow-up trigger; it is not permission to
   pad a narrow concept or waive whole-question coverage. Seed from the first pass, non-doc sources
   first. Already-read source tiers alone do not trigger repetition. Merge and
   scope-check the result even when the first pass stands alone; retain off-topic
   claims privately and hand adjacent concepts to CFE. Quick keeps one pass;
   saturate keeps its independent passes and measured empty-round loop.
6. Store complete canonical claims, source links, question coverage and all
   attempt references under the concept's fenced revision. Broadening twice
   without meeting authority floors blocks that concept. Do not mark a worker
   return or successful write as researched/qualified completion.
7. Render skill text from canonical claims, with a capability description,
   discriminating TRIGGER/SKIP boundaries, scope and citations. Route to an
   existing qualified hub when appropriate; preserve stable concept identity and
   aliases. Store the skill artifact in Mongo. Scan for source injection.
8. Call trusted `research_finalize` and inspect its terminal receipt. A trusted
   gate failure triggers only the bounded pair-specific repair in evidence.md.
   Save the exact successful gate/artifact references. Compile qualified claims
   with `research_compile` when packs are part of the requested output. Server
   finalization and compilation may generate their own canonical skill projection;
   inspect the accepted artifact rather than assuming the draft was installed.
9. Verify whole-question coverage and required projection receipts before a full
   completion verdict. A saved expert skill is an artifact, not proof the client
   installed it; report installation only when that host provides a receipt.

On refresh, preserve accepted historical artifacts and paid attempts. Recheck
volatile claims, changed applicability and uncovered questions only. Resume from
the saved unfinished phase; a rendering, compile or website projection failure
does not restart discovery. Report actual run state, concepts/claims, authority
gaps, accepted skill/artifact IDs, gate and projection status, cost/tokens when
reported, and all remaining work.
