## Problems, failure modes and limitations

- [statement] The customer endpoint is a boundary of available evidence, not a universal PrivateLink product limit: AWS supports tracing to service targets within an organization, and Serverworks independently demonstrated analysis between consumer and provider EC2 instances across a PrivateLink lab topology. That lab does not establish access to Atlas-managed resources. (medium confidence) — https://aws.amazon.com/about-aws/whats-new/2023/03/amazon-vpc-reachability-analyzer-3-networking-services/ · keywords: Reachability Analyzer scope for customer-owned Atlas PrivateLink paths · also: https://blog.serverworks.co.jp/privatelink-ci-explanation
- [statement] Reachability Analyzer does not consider registered-target health. A customer-endpoint path result therefore cannot establish that the Atlas-side load-balancer targets are healthy. (low confidence) — https://docs.aws.amazon.com/vpc/latest/reachability/how-reachability-analyzer-works.html
- [statement] For TCP analyses whose path traverses a transit-gateway route table, AWS examines only forward traffic. That modeled result cannot establish a complete return path. (low confidence) (verified as of 2026-10-31) — https://docs.aws.amazon.com/vpc/latest/reachability/how-reachability-analyzer-works.html

## Facts and statements

- [statement] For an Atlas PrivateLink investigation, a defensible customer-side analysis ends at the interface endpoint or its ENI: AWS supports VPC endpoints and network interfaces as destinations, while MongoDB distinguishes that interface endpoint from the Atlas-created endpoint service and load balancer. This boundary is a synthesis of the two vendors’ documentation, not an Atlas-specific test. (medium confidence) — https://docs.aws.amazon.com/vpc/latest/reachability/how-reachability-analyzer-works.html · keywords: Reachability Analyzer scope for customer-owned Atlas PrivateLink paths · also: https://www.mongodb.com/docs/atlas/security-private-endpoint.md
- [statement] Cross-account Reachability Analyzer analysis requires AWS Organizations trusted access. Management accounts can analyze organization accounts; delegated administrators can analyze other organization accounts except the management account, plus explicitly shared management-account resources. AWS describes PrivateLink target tracing within the organization. Owning an Atlas-facing endpoint therefore does not itself establish permission to inspect Atlas-owned service-side resources; provider-side access must be separately demonstrated. - [statement] Reachability Analyzer builds a configuration model without sending packets or analyzing the data plane.
