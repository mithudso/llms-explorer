## Structure and components

- [statement] In static containers, component versions are pinned to their container images and are not automatically upgraded. Advancing a pinned component therefore requires deploying a replacement image that contains its intended version; changing the MongoDB server version alone does not establish an Agent upgrade. (low confidence) (verified as of 2026-10-14) — https://www.mongodb.com/docs/kubernetes/current/tutorial/plan-k8s-op-container-images.md

## How it works

- [statement] For MongoDB database version upgrades, non-static deployments use the MongoDB Agent, whereas static deployments use the Kubernetes Operator to replace container images and trigger a rolling restart. The database-version upgrade procedure sets spec.version and reapplies the MongoDB resource. (medium confidence) (verified as of 2026-10-14) — https://www.mongodb.com/docs/kubernetes/current/tutorial/plan-k8s-op-container-images.md · keywords: MongoDB Agent upgrade policy in static versus non-static containers · also: https://www.mongodb.com/docs/kubernetes/current/tutorial/upgrade-mdb-version.md
- [statement] Enterprise Kubernetes Operator 1.33.0 release notes record a fix for static workloads that still downloaded binaries when the Operator default was non-static and the workload used mongodb.com/v1.architecture: "static". This historical implementation bug scopes any claim that the static annotation alone always prevented runtime downloads. (low confidence) — https://github.com/mongodb/mongodb-kubernetes/blob/master/RELEASE_NOTES_MEKO.md

## Problems, failure modes and limitations

- [statement] For static deployments with Cloud Manager, the documentation warns that the Agent can fall behind compatibility because the Operator cannot call Cloud Manager's agentVersion endpoint. It specifies either overriding the mongodb-agent StatefulSet container image through the MongoDB resource specification with a compatible Agent image, or upgrading the Operator to its latest version to update the Agent. (low confidence) (verified as of 2026-10-14) — https://www.mongodb.com/docs/kubernetes/current/tutorial/plan-k8s-op-container-images.md

## Facts and statements

- [statement] MongoDB's container comparison says Ops Manager may automatically upgrade the MongoDB Agent, BI Connector, and MongoDB Database Tools to the latest compatible versions in non-static containers; this is conditional capability, not a guarantee that every deployment upgrades automatically. (low confidence) (verified as of 2026-10-14) — https://www.mongodb.com/docs/kubernetes/current/tutorial/plan-k8s-op-container-images.md
- [statement] For static deployments managed by Ops Manager, the documentation says the Operator automatically selects the appropriate Agent container version based on the selected Ops Manager version. This image selection is distinct from an Agent updating itself inside a running container. (low confidence) (verified as of 2026-10-14) — https://www.mongodb.com/docs/kubernetes/current/tutorial/plan-k8s-op-container-images.md
- [statement] The kubectl installation reference scopes AGENT_IMAGE, including its version, to non-static database deployments. Static-container planning instead uses MDB_AGENT_IMAGE_REPOSITORY for the Agent image repository. Selecting a repository location does not itself specify a newer Agent binary version and should not be confused with the static Cloud Manager image-version override. (low confidence) (verified as of 2026-10-14) — https://www.mongodb.com/docs/kubernetes/current/reference/kubectl-operator-settings.md · keywords: MongoDB Agent upgrade policy in static versus non-static containers · also: https://www.mongodb.com/docs/kubernetes/current/tutorial/plan-k8s-op-container-images.md
- [statement] A June 10, 2026 maintainer reply in issue #1008 described dependency-update automation that would change the Community Operator's Agent image from 108.0.2.8729-1 to 108.0.23.8997-1. This is historical evidence of updating an image dependency, not proof of the Enterprise static-container policy or of a universally safe Agent override. (low confidence) (verified as of 2026-06-10) — https://github.com/mongodb/mongodb-kubernetes/issues/1008
