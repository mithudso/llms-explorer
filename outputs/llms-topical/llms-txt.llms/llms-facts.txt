### The spec, v2

- [statement] Placement and scope (new in v2). "The llms.txt file spec is for files named `llms.txt`, at the root path `/llms.txt` of a website or at any subpath (e.g. `/docs/llms.txt`). A file covers the URLs under its path, and where more than one file applies, agents should use the most specific one." This is what lets a project that only controls a path (a GitHub Pages site) participate, and it is the mechanism for hub-and-spoke indexes (see sibling *recreation-and-aggregation*). — https://llmstxt.org/ · keywords: llms.txt, /llms.txt, /docs/llms.txt · verified-as-of: 2026-08-30 · also: https://llmstxt.org/index.md
- [statement] Consumption expectation (v2). "Agents are expected to view or search `llms.txt` to find the information they need, then follow the relevant links … The file itself stays small enough to fit in context. The detail lives behind the links, and is fetched only when needed." Authoring guidance in the spec: concise language, informative link descriptions, no unexplained jargon, and "test your file by asking an agent questions about your content, giving it only your llms.txt as a starting point." — https://llmstxt.org/ · keywords: llms.txt · verified-as-of: 2026-08-30 · also: https://llmstxt.org/index.md
- [statement] What v2 changed and why (llmstxt.org/changes): link-relation discovery added; both `.md` URL forms allowed; subpath semantics defined; `llms_txt2ctx` removed from the proposal and with it the special meaning of `Optional`; background rewritten around how agents actually use sites. — https://llmstxt.org/changes.md · keywords: .md, llms_txt2ctx, Optional · verified-as-of: 2026-08-30

- [definition] The links should point at clean markdown (a `.md` twin of each page), so the index stays small enough for context and the detail is fetched only when needed. — https://llmstxt.org/ · keywords: .md · verified-as-of: 2026-08-30 · also: https://llmstxt.org/index.md, https://llmstxt.org/changes.md

## llms.txt recreation and family aggregation

### Decide what you are allowed to make

- [statement] An llms.txt for a third-party site is a link list plus short descriptions — the same thing a search engine publishes; it is low-risk. An llms-full.txt for a third-party site is a stored republication of their content: closer to `ai-train`/redistribution than to transient `ai-input` retrieval. — https://blog.cloudflare.com/content-signals-policy/ · keywords: ai-train, ai-input · verified-as-of: 2026-08-30 · also: https://www.scrapingbee.com/blog/is-web-scraping-legal/
- [statement] Keep such full-text mirrors private/internal unless the licence allows republication; publish only the index. — https://blog.cloudflare.com/content-signals-policy/ · verified-as-of: 2026-08-30 · also: https://www.scrapingbee.com/blog/is-web-scraping-legal/
- [statement] Read `robots.txt` first: the sitemap pointer, disallow rules, and any Cloudflare Content Signals line (`Content-Signal: search=yes, ai-input=…, ai-train=no`), which is framed as an express reservation of rights under EU Directive 2019/790 Art. 4 even though no crawler enforces it. robots.txt is "a polite request, not legally binding", but ignoring it invites blocking. — https://blog.cloudflare.com/content-signals-policy/ · keywords: robots.txt, Content-Signal: search=yes, ai-input=…, ai-train=no · verified-as-of: 2026-08-30 · also: https://www.seroundtable.com/google-cloudflare-content-signals-41631.html, https://www.scrapingbee.com/blog/is-web-scraping-legal/
- [actionable] Prefer the site's own machine-readable surfaces where they exist (an llms.txt, `.md` twins, `Accept: text/markdown`, a docs API such as GitHub's Article Body API) — the owner has already chosen what to expose. — https://llmstxt.org/ · keywords: .md, Accept: text/markdown · verified-as-of: 2026-08-30 · also: https://docs.github.com/llms.txt

### Scale to a family: nested indexes, hub-and-spoke
