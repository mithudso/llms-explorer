# Prompt caching — concept pack (small)

> Prompt caching lets the API reuse an already-processed prompt prefix (tools → system → messages) across requests to cut cost and latency: Anthropic offers automatic caching or explicit `cache_control: {"type": "ephemeral"}` breakpoints with 5-minute or 1-hour TTLs, bills cache writes at 1.25×/2× and cache hits at 0.1× the base input price, and reports them in usage.cache_creation_input_tokens / cache_read_input_tokens; OpenRouter passes cache_control through to Anthropic and Gemini, adds provider sticky routing, and documents OpenAI automatic caching. Two of the three docsets contributed (the OpenAI export is empty).

## Definitions

- [definition] Automatic caching — Automatic caching is the simplest way to enable prompt caching. Instead of placing `cache_control` on individual content blocks, add a single `cache_control` field at the top level of your request body. — https://platform.claude.com/docs/en/build-with-claude/prompt-caching#automatic-caching
- [definition] Prompt caching — Prompt caching doesn't reduce the number of tokens in context, but it reduces what you pay for them on subsequent requests. If your tool definitions are stable, cache them once and reuse the cached prefix across thousands of requests. — https://platform.claude.com/docs/en/agents-and-tools/tool-use/manage-tool-context#prompt-caching
- [definition] Cache miss reason types — `cache_miss_reason` is a discriminated union on `type`. The response reports the earliest divergence only, so fix it first; later ones may be hidden behind it. — https://platform.claude.com/docs/en/build-with-claude/cache-diagnostics#cache-miss-reason-types
- [definition] Caching — Some endpoints/models provide implicit caching of prompts. This keeps repeated prompt data in an in-memory cache in the provider's datacenter, so that the repeated part of the prompt does not need to be re-processed. — https://openrouter.ai/docs/guides/features/zdr#caching · keywords: automatic caching · note: OpenRouter's description of provider implicit caching

- [definition] How automatic caching works in multi-turn conversations — With automatic caching, the cache point moves forward automatically as conversations grow. ## How-to and procedures

- [definition] Mixing different TTLs — You can use both 1-hour and 5-minute cache controls in the same request, but with an important constraint: Cache entries with longer TTL must appear before shorter TTLs (that is, a 1-hour cache entry must appear before any 5-minute cache entries). — https://platform.claude.com/docs/en/build-with-claude/prompt-caching#mixing-different-ttls
- [definition] cache\_control on tool definitions — Place `cache_control: {"type": "ephemeral"}` on the last tool in your `tools` array. This caches the entire tool-definitions prefix, from the first tool through the marked breakpoint: — https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-use-with-prompt-caching#cache-control-on-tool-definitions
- [idea] Consider using the 1-hour cache duration with prompt caching for batches with shared context to improve cache hit rates, as processing can take longer than 5 minutes. — https://platform.claude.com/docs/en/build-with-claude/batch-processing#how-the-message-batches-api-works
- [definition] Structuring your prompt — Place static content (tool definitions, system instructions, context, examples) at the beginning of your prompt. Mark the end of the reusable content for caching using the `cache_control` parameter. — https://platform.claude.com/docs/en/build-with-claude/prompt-caching#structuring-your-prompt
- [definition] How to Enable Gemini Prompt Caching: — Gemini caching in OpenRouter requires you to insert `cache_control` breakpoints explicitly within message content, similar to Anthropic. — https://openrouter.ai/docs/guides/best-practices/prompt-caching#how-to-enable-gemini-prompt-caching
- [idea] Use prompt caching to reduce cost and latency by caching prompt prefixes shared across requests in a batch. — https://platform.claude.com/docs/en/build-with-claude/batch-processing#next-steps
- [definition] When to use the 1-hour cache — If you have prompts that are used at a regular cadence (that is, system prompts that are used more frequently than every 5 minutes), continue to use the 5-minute cache, because this will continue to be refreshed at no additional charge. — https://platform.claude.com/docs/en/build-with-claude/prompt-caching#when-to-use-the-1-hour-cache

## Comparisons and alternatives
