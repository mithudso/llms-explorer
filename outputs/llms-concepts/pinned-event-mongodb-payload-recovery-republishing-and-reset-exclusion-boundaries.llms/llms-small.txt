## How it works

- [statement] For each loaded payload entry, recovery adds its original message ID to the handled set before checking EventName. An empty EventName causes a skip with no Send and no recovery-count increment; that original ID remains excluded from reset during the same pass. The code comment identifies entries written before EventName was added as the reason for this guard. (low confidence) — https://raw.githubusercontent.com/rbaliyan/event/b112463682d44b0e57d8545e3cdf5d51e112e914/distributed/recovery.go

## Problems, failure modes and limitations

- [statement] A Send error skips marking and clearing, retains the payload for a later recovery cycle, and leaves the original ID in the same-pass reset exclusion set. The failing-publisher memory fixture asserts that RecoverOnce returns zero recovered and no pass error in that case. (medium confidence) — https://raw.githubusercontent.com/rbaliyan/event/b112463682d44b0e57d8545e3cdf5d51e112e914/distributed/recovery.go · keywords: Pinned event-mongodb payload recovery republishing and reset exclusion boundaries · also: https://raw.githubusercontent.com/rbaliyan/event/b112463682d44b0e57d8545e3cdf5d51e112e914/distributed/payload_test.go
- [statement] After Send succeeds, recovery calls MarkProcessed on the original ID before ClearPayload. A MarkProcessed error retains the payload, skips the count increment, and preserves same-pass reset exclusion. A later recovery cycle can send the payload again; the runner comment explicitly warns that a crash between republishing and marking can also cause another republish. (low confidence) — https://raw.githubusercontent.com/rbaliyan/event/b112463682d44b0e57d8545e3cdf5d51e112e914/distributed/recovery.go
- [statement] After MarkProcessed returns nil, recovery ignores the ClearPayload error and increments recovered. In MongoStateManager, MarkProcessed updates status to completed while ClearPayload unsets only payload. Thus, if marking updates an existing document and clearing then fails, the retained payload alone does not satisfy LoadStalePayloads, which requires processing status. (medium confidence) — https://raw.githubusercontent.com/rbaliyan/event/b112463682d44b0e57d8545e3cdf5d51e112e914/distributed/recovery.go · keywords: Pinned event-mongodb payload recovery republishing and reset exclusion boundaries · also: https://raw.githubusercontent.com/rbaliyan/event-mongodb/ca444aedec31e7e959c0932a8f7577c15312f37e/distributed/mongodb.go
- [statement] The positive batch budget for reset is batchLimit minus the count of successful payload recoveries, while LoadStalePayloads receives the original batchLimit. Skipped payload entries do not consume that success count. ListStale receives the remaining limit before exclusion, so excluded IDs can reduce useful reset work without a refill. A zero batchLimit means unlimited; the memory zero-limit fixture asserts recovery of all three stale entries. (medium confidence) — https://raw.githubusercontent.com/rbaliyan/event/b112463682d44b0e57d8545e3cdf5d51e112e914/distributed/recovery.go · keywords: Pinned event-mongodb payload recovery republishing and reset exclusion boundaries · also: https://raw.githubusercontent.com/rbaliyan/event/b112463682d44b0e57d8545e3cdf5d51e112e914/distributed/payload_test.go
- [statement] LoadStalePayloads, ListStale or bulk ResetStale errors propagate as pass errors. In contrast, individual Send, MarkProcessed and Reset failures are recorded and skipped, and ClearPayload errors are ignored. RecoverOnce returns the successful payload total if its reset helper reports an error. ## Comparisons and alternatives

- [statement] MongoStateManager stores payload on the existing message document, with metadata and event name set only when nonempty; nil data or an empty payload returns without writing. LoadStalePayloads selects processing documents whose updated_at precedes the stale cutoff and whose payload field exists, applies a positive query limit, and reconstructs payload, metadata and event name. These predicates use updated_at rather than expires_at. (low confidence) — https://raw.githubusercontent.com/rbaliyan/event-mongodb/ca444aedec31e7e959c0932a8f7577c15312f37e/distributed/mongodb.go
- [statement] MongoStateManager MarkProcessed filters by message ID and returns nil when UpdateOne returns no error; it does not inspect matched or modified counts. Therefore, the runner counts a nil marking result rather than independently verifying a completed-state transition. (medium confidence) — https://raw.githubusercontent.com/rbaliyan/event-mongodb/ca444aedec31e7e959c0932a8f7577c15312f37e/distributed/mongodb.go · keywords: Pinned event-mongodb payload recovery republishing and reset exclusion boundaries · also: https://raw.githubusercontent.com/rbaliyan/event/b112463682d44b0e57d8545e3cdf5d51e112e914/distributed/recovery.go
