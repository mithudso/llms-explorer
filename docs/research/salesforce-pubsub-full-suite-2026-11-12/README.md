## Proposed system direction

Use one authorized upstream collector, durable MongoDB intake and a queryable alert journal, followed by an authenticated application service that pushes to devices. Keep source replay, materializer progress, journal position, device receipt and user read state distinct. An optional authorized device-first observation can enter a provisional deduplicated intake path; it does not replace authoritative discovery.

This composition is a proposal. Baseline hydration, reconciliation, dedupe identity, fencing enforcement, regional authority, physical shard keys and device recovery need implementation and acceptance evidence. An approved existing synchronization feed can also serve central intake; reducing repeated tertiary reads does not imply zero scheduled queries throughout every upstream path. The architecture assessment gives concrete proposed fields and queries without claiming a configured or tested deployment.
