# Informed Clearly: expanded guide

> A detailed map of the public Informed Clearly website for search engines, assistants, agents, feed readers, and other automated clients.

The canonical site is [https://informedclearly.com/](https://informedclearly.com/). Public editorial content is available without authentication. Respect [robots.txt](https://informedclearly.com/robots.txt), response cache headers, and normal rate limits. Do not attempt to access CMS, account, submission-status, or internal API routes.

Pages expose reciprocal `hreflang` links. Use the requested language when available, otherwise prefer English. The site root is the `x-default` entry point.

## Canonical public page patterns

- `/{lang}/` — language homepage
- `/{lang}/news` and `/{lang}/news/{page}` — current news listings
- `/{lang}/articles` and `/{lang}/articles/{page}` — in-depth article listings
- `/{lang}/{category}` and `/{lang}/{category}/{page}` — category listings
- `/{lang}/{category}/{id}/{slug}` — canonical article
- `/{lang}/summary` and `/{lang}/summary/{date}` — daily briefings
- `/{lang}/authors` and `/{lang}/authors/{author-slug}` — authors
- `/{lang}/finance` and `/{lang}/finance/{asset}` — finance pages
- `/{lang}/about`, `/{lang}/contact`, `/{lang}/privacy-policy`, `/{lang}/terms`, `/{lang}/editorial-policy`, and `/{lang}/corrections-policy` — trust and policy pages

The valid language codes are `en`, `nl`, `de`, `fr`, `es`, and `pt`. Follow page canonicals rather than constructing slugs. Remove tracking parameters such as `utm_*`, `ref`, `fbclid`, and `gclid` when storing or citing URLs.

## Public API

- [OpenAPI YAML](https://informedclearly.com/openapi.yaml)
- [OpenAPI JSON](https://informedclearly.com/openapi.json)
- [Languages endpoint](https://informedclearly.com/api/languages)
- [Article search](https://informedclearly.com/api/articles?lang=en&per_page=10)
- [Latest article](https://informedclearly.com/api/articles/latest?lang=en)

The API is unauthenticated and read-only. Supported operations are:

- `GET /api/languages`
- `GET /api/articles`
- `GET /api/articles/{id}`
- `GET /api/articles/latest`
- `GET /api/articles/by-url?url={encoded-canonical-url}`

Article search accepts optional `q`, `lang`, `category`, `author`, `date_from`, and `date_to` filters. Pagination is one-based; `per_page` must be between 1 and 50. Dates use `YYYY-MM-DD`. Invalid parameters return a 4xx JSON error rather than being silently changed.

Article responses provide a canonical `url`, citation metadata, provenance metadata, publication time, language, and an image URL where available. Cite the canonical HTML `url`, not the API request URL.

## Article interpretation

Article pages provide a headline, publication and modification time, author, category, image, structured data, and a “How we know” section where source links are available. Preserve the distinction between reported facts, analysis, and source material. For corrections or questions, use the published policy and contact routes.

## Citation guidance

A useful citation includes the article title, publisher, and canonical URL:

`Source: Informed Clearly — Article title (https://informedclearly.com/{lang}/{category}/{id}/{slug})`

Short quotations and summaries should be attributed. Do not present an API response, search result, or related-story match as a separate publication when it points to an existing canonical article.
