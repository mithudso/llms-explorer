## How it works

- [statement] MongoDB 8.0 documents the following additional transaction-stage exclusion matrix: $collStats—disallowed; $currentOp—disallowed; $listLocalSessions—disallowed; $listSessions—disallowed; $planCacheStats—disallowed. The same two release references also list $indexStats as disallowed; that row is inherited baseline context, not a new delta. These are stage exclusions even when the pipeline does not write results. (high confidence) (verified as of 2026-10-31) — https://www.mongodb.com/docs/v8.0/core/transactions-operations/ · keywords: Transaction aggregation-stage eligibility beyond write-stage bans · also: https://www.mongodb.com/docs/v8.0/reference/command/aggregate/
- [statement] MongoDB 8.0 prohibits $graphLookup inside a transaction when its target collection is sharded. The stage reference identifies the target as the from collection, which must be in the same database as the other collections used by the operation. General support for a sharded from collection since 5.1 does not remove this transaction restriction. (high confidence) (verified as of 2026-10-31) — https://www.mongodb.com/docs/v8.0/reference/operator/aggregation/graphLookup/ · keywords: Transaction aggregation-stage eligibility beyond write-stage bans · also: https://www.mongodb.com/docs/v8.0/core/transactions/

## Problems, failure modes and limitations

- [statement] MongoDB 8.0 transactions containing reads require primary read preference. Read-only aggregation therefore cannot use a secondary preference merely because it has no write stage; the driver transaction specification explicitly requires a primary preference for transactional reads. (medium confidence) — https://www.mongodb.com/docs/v8.0/core/transactions/ · keywords: Transaction aggregation-stage eligibility beyond write-stage bans · also: https://github.com/mongodb/specifications/blob/master/source/transactions/transactions.md

## Facts and statements

- [statement] For $planCacheStats in MongoDB 8.0, using read concern local and placing the stage first do not make it transaction-eligible. The stage documentation independently requires local read concern and bans transactions; the r8.0.0 implementation sets TransactionRequirement::kNotAllowed and its LiteParsed::assertSupportsMultiDocumentTransaction calls transactionNotSupported. (high confidence) (verified as of 2026-10-31) — https://www.mongodb.com/docs/v8.0/reference/operator/aggregation/planCacheStats/ · keywords: Transaction aggregation-stage eligibility beyond write-stage bans · also: https://raw.githubusercontent.com/mongodb/mongo/r8.0.0/src/mongo/db/pipeline/document_source_plan_cache_stats.h, https://www.mongodb.com/docs/v8.0/reference/command/aggregate/
- [statement] MongoDB 8.0 prohibits transaction reads as well as writes to collections in the config, admin and local databases. A transaction may span different application databases, but that does not waive these database exclusions. Alibaba ApsaraDB and Huawei DDS documentation separately state the same namespace exclusions for their services; their service/version scope does not establish the MongoDB 8.0 stage matrix.
