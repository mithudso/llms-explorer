# Apple Intelligence — privacy-foundations-1

## Overview

Private Cloud Compute (PCC) is Apple's purpose-built confidential inference system for Apple Intelligence requests that exceed on-device capability. Its trust boundary centers on an attested compute node: request content is available to inference code, while Apple's design says external infrastructure and operators lack plaintext access and data is deleted after use. Devices verify node measurements against a public append-only release log; Apple publishes images, a Virtual Research Environment, and selected source for independent inspection. These artifacts make the architecture more inspectable than an opaque general cloud service, but they do not prove every deployed binary or the complete attestation chain. Independent researchers have reported concrete gaps in request authentication, writable configuration measurement, and certificate revocation.

Apple Intelligence Report is a user-controlled activity export in Privacy & Security. Current iOS 27 and macOS 27 guides describe a 15-minute default or 7-day report window, an Off choice, and manual export to Apple_Intelligence_Report.json. The report documents activity for a bounded window; it is not a general retention promise or a complete, independently authenticated audit. Published samples and parser work indicate that the JSON can expose sensitive request text. The exact presence of on-device entries remains unclear because Apple's user guides and a 2026 parser study describe different scopes.

Apple’s ChatGPT extension is an optional external-provider route from supported Apple Intelligence features. Enabling it is required, but request consent differs by flow: version 26 can send explicit “Ask ChatGPT” requests directly and lets users suppress some Siri confirmation prompts, while photos and files still require confirmation; OpenAI says Siri AI (Beta) does not allow request confirmation to be disabled. A handoff can include the selected prompt, attachments, and limited request context; Apple obscures the IP address but shares approximate location. Without a ChatGPT account, OpenAI says requests are not stored or used for training except where law requires. Linking an account applies OpenAI settings and may save history or allow service improvement based on those settings. Apple separately collects limited service metadata. These disclosures describe the external ChatGPT route; Apple-run processing and PCC disclosures do not define OpenAI’s account policy.

Public disclosure moves from a dense ~3B on-device language model plus a larger server language model in 2024, to a multimodal 3B on-device model and PT-MoE server model in 2025, then to a named five-model family in 2026. AFM 3 Core Advanced adds a sparse 20B on-device tier with 1–4B active per request, while ADM 3 Cloud is the named image-generation model. Apple reports training and evaluation methods, including preference comparisons with its 2025 baseline; these remain Apple-reported. The broader family already included a diffusion model in 2024. Current OS 27 availability is documented, but support pages do not map every AFM/ADM variant to each feature.

## Core Concepts

### Private Cloud Compute trust architecture and verification

- PCC is not end-to-end encrypted against the inference node: the node must read request content to generate a response. In Apple’s Apple-silicon design, the device encrypts directly to attested PCC nodes, while relays and supporting load-balancing services sit outside the decryption boundary. This is a measured processing boundary, not ordinary TLS-only cloud hosting.[^c1-1][^c1-2]
- Apple defines PCC’s stateless requirement as using request data only to fulfill that request, deleting it after the response, and retaining no user data through logging or debugging. Apple describes enforcement measures including per-reboot data-volume key randomization by the Secure Enclave and recycling memory address spaces; these are vendor-described controls, not an independent proof that no implementation defect can retain data.[^c1-1][^c1-2][^c1-3]
- In Apple's original Apple-silicon design, the attested PCC node is the request decryption trust boundary: load balancers and privacy gateways sit outside it and lack request keys. Apple says the node omits remote shells, interactive debugging, and general-purpose logging, and allows only pre-specified, structured, audited logs and metrics to leave; inference code inside the node still processes request content.[^c1-1][^c1-2]
- Apple defines non-targetability as preventing a limited compromise from steering a selected user's requests to compromised nodes. Its design uses unlinkable single-use credentials, a third-party OHTTP relay that hides the source IP, and load balancing over a node subset chosen without user identity; independent ACM researchers also describe OHTTP and randomized node selection.[^c1-1][^c1-2]
- Apple's verifiable-transparency design links device-side attestation to an append-only public log of software measurements and public images for production releases. Apple also offers a Virtual Research Environment that can boot PCC releases and verify log consistency, plus source for selected security-critical components such as CloudAttestation, Thimble, and splunkloggingd.[^c1-1][^c1-4][^c1-5][^c1-6]
- On 2026-06-08 Apple announced extending PCC beyond Apple data centers to Google Cloud using NVIDIA Confidential Computing, Intel TDX, and Google Titan. Apple says the core PCC requirements remain and that the Google Cloud design treats firmware through application software as part of the trusted computing base, with an append-only hardware ledger and at least two independent vendor roots for components that could exfiltrate data. This is an announced architecture, not evidence that its combined protections have been independently tested against every TEE attack. (two sources) verified-as-of: 2026-06-08[^c1-11][^c1-7]
- For the Apple-silicon PCC flow, Apple documents device-side attestation of the node’s operating system and loaded cryptexes. The client verifies that the measured release has an inclusion proof in a public append-only transparency log before wrapping the request key to that node. The current documentation describes a 14-day release-entry lifetime and a 7-day grace period before a user alert for an unresolved log consistency error. verified-as-of: 2026-10-23[^c1-5][^c1-1]
- Apple’s non-targetability design aims to prevent a limited compromise from steering a particular user’s requests to a compromised node. Apple describes anonymous authorization, a third-party OHTTP relay, and selection of a subset of nodes; its current guide also says the relay may expose a rough geographic region and requests may carry basic product and operating-system build headers outside the encrypted payload. Apple cautions that a user distinguishable by these properties could be exposed to a semi-targeted attack. verified-as-of: 2026-10-23[^c1-13][^c1-1][^c1-2][^c1-15]
- On June 8, 2026, Apple announced an extension of PCC to Google Cloud using NVIDIA Confidential Computing GPUs, Intel TDX CPUs and Google’s Titan chip. Apple said the same five core requirements would apply, with at least two independent vendor roots of trust for components that could exfiltrate data, and described protections as ramping during a summer preview. That dated announcement does not establish the deployment’s status after the preview. verified-as-of: 2026-06-08[^c1-11][^c1-1]

### Apple Intelligence Reports and user privacy controls

- Apple's current iOS 27 and macOS 27 user guides direct users to Privacy & Security > Apple Intelligence Report, allow a last-15-minutes window (the default), a last-7-days window, or Off, and say Export Activity saves Apple_Intelligence_Report.json to a location the user chooses. verified-as-of: 2026-10-23[^c2-1][^c2-2][^c2-8][^c2-10]
- Apple describes the report as a record of requests sent to Private Cloud Compute and warns that it can be empty when no PCC requests occurred since the duration changed. 9to5Mac reported empty seven-day exports in its 2025 checks, while Daring Fireball found that Writing Tools Proofread produced no entry but Summarize produced a PCC entry. An empty export therefore does not prove that Apple Intelligence was unused; it can reflect the chosen capture window and which tasks reached PCC. (two sources) verified-as-of: 2026-10-23[^c2-1][^c2-5][^c2-4]
- Published report samples indicate that the exported JSON can expose sensitive request content. AppleInsider's iOS 18.1 inspection described timestamps, request identifiers, optional task text, and software-component details; a July 2026 parser study lists prompt and response fields in modelRequests, and a September 2026 guide also describes those fields. Treat the export as potentially sensitive, and treat its exact fields as version-specific rather than a stable public schema. (two sources) verified-as-of: 2026-09-24[^c2-3][^c2-6][^c2-7]
- The Off choice disables the report setting, not Apple Intelligence itself: Apple's guides label it as turning off the report, and a September 2026 field guide says requests may still go to PCC when features need it. Users should read Off as stopping report capture rather than stopping Apple Intelligence processing. (two sources) verified-as-of: 2026-10-23[^c2-1][^c2-2][^c2-7]
- Apple Intelligence Report modelRequests entries can expose timestamps and request identifiers, prompt and response text, model and modelVersion, clientIdentifier, and executionEnvironment; observed schemas may also include useCase. Prompt and response fields can contain personal content, so handle the exported JSON as sensitive. verified-as-of: 2026-09-22[^c2-9][^c2-6][^c2-2]

### External intelligence and ChatGPT handoff consent

- Apple’s current 27.0 support page lists the ChatGPT extension among supported iPhone, iPad, Mac, and Apple Vision Pro features. OpenAI’s setup page separates that extension from Siri AI, which it labels Beta, and says confirmation controls depend on whether Siri AI is active. verified-as-of: 2026-10-23[^c3-4][^c3-3]
- The ChatGPT extension must first be enabled and is off by default. In the version 26 Siri flow, an explicit “Ask ChatGPT” request goes directly to ChatGPT; inferred handoff asks for confirmation by default, and users can turn off that prompt, but photos and files still require confirmation. With Siri AI (Beta), OpenAI says request confirmation cannot be disabled and users must explicitly invoke ChatGPT. verified-as-of: 2026-10-23[^c3-1][^c3-3]
- A ChatGPT handoff can include the request, chosen attachments or document contents, and limited context such as time zone, country, device type, language, and the feature in use. Apple says it obscures the user’s IP address from ChatGPT while providing an approximate general location for fraud prevention and legal compliance. verified-as-of: 2026-10-20[^c3-1][^c3-2]
- Without a connected ChatGPT account, OpenAI says it processes requests to provide a response and comply with law, does not receive the user’s IP address, does not store requests, and does not train on them. Apple says OpenAI receives no information tied to the user’s Apple Account and must not retain or train on the request except where law requires it. verified-as-of: 2026-10-20[^c3-1][^c3-2]
- Signing in is optional, but it changes the data-policy boundary: OpenAI account settings and privacy policies then apply. OpenAI says conversations may be saved in ChatGPT history and used to improve services depending on account settings and use; Apple’s notice says OpenAI may log requests, attachments, and session history and may use signed-in data to improve or train models. OpenAI exposes an “Improve the model for everyone” control for model improvement. verified-as-of: 2026-10-20[^c3-1][^c3-2]
- OpenAI says connecting the account makes the account’s name, email, profile image, workspace names, and billing plan available on the device to complete the link; its integration page says existing OpenAI data preferences apply to Apple-originated conversations. The pages describe these fields as device-level connection data and do not say they are sent to Apple. (two sources) verified-as-of: 2026-10-23[^c3-3][^c3-2]
- Tentative: Apple collects limited request and response metadata, such as request counts or approximate sizes, to operate the extension and prevent fraud. If users opt in to Improve Siri and Dictation or Improve Siri & Apple Intelligence, Apple may also log request audio, transcripts, and response metadata; Apple says these records are not tied to the Apple Account. verified-as-of: 2026-09-14[^c3-1]
- A June 2024 independent analysis republished by TechXplore listed whether every ChatGPT action required explicit consent as an unanswered question. Current Apple and OpenAI instructions now describe different consent rules by OS flow and request type, so launch-era summaries of one universal prompt are not a reliable current rule. (two sources) verified-as-of: 2026-10-23[^c3-6][^c3-1][^c3-3]
- Apple says the ChatGPT extension is off by default, must be enabled before use, and can be disabled at any time. OpenAI says a ChatGPT account is optional: users can set up the integration without signing in. verified-as-of: 2026-10-23[^c3-1][^c3-3]
- In the standard Siri flow, an explicit request to use ChatGPT is treated as authorization and goes directly to ChatGPT; if Siri determines ChatGPT might help without an explicit request, it asks first. The user can disable that confirmation. Writing Tools and Visual Intelligence offer a separate choice to use the extension. verified-as-of: 2026-10-23[^c3-1][^c3-3]
- Tentative: OpenAI's current setup guide says Siri AI confirmation cannot be disabled and users must explicitly ask Siri to use ChatGPT before sending a prompt, photo, or file. For non-Siri-AI version 26, the guide says beginning a request with “Ask ChatGPT” skips the prompt for that request, while photos and files still require confirmation. verified-as-of: 2026-10-23[^c3-3]
- When a user links a ChatGPT account, OpenAI's existing data preferences and privacy policies govern the handoff. Chats can be saved in account history, and model improvement depends on account choices. OpenAI says the device receives basic account fields for linking, including name, email, profile image, workspace names, and billing plan. verified-as-of: 2026-10-19[^c3-1][^c3-2][^c3-5]

### AFM 3 and ADM model family architecture evolution

- The 2024 technical report defines the AFM pair as an approximately 3-billion-parameter on-device language model and a larger server language model. It describes the AFM base models as dense decoder-only Transformers and places coding and diffusion/image models in the broader generative family. verified-as-of: 2026-05-27[^c4-1][^c4-2]
- Apple's 2024 report says the wider generative-model family already included coding and diffusion models; its June 2026 article names ADM 3 Cloud (Image) for image generation and editing, so 2026 was not the first public disclosure of an Apple Intelligence image-model branch. verified-as-of: 2026-06-08[^c4-1][^c4-3]
- Apple's 2025 report describes two multilingual, multimodal language models: an approximately 3B on-device model with two-block KV-cache sharing and 2-bit quantization-aware training, and a server PT-MoE model using track parallelism and interleaved global/local attention. Apple reports the KV-cache design reduces cache memory by 37.5%. verified-as-of: 2025-08-27[^c4-4][^c4-5]
- In its June 8, 2026 announcement, Apple names five models: AFM 3 Core, a dense approximately 3-billion-parameter on-device model; AFM 3 Core Advanced, a natively multimodal 20-billion-parameter sparse on-device model with 1–4 billion active parameters; AFM 3 Cloud, a server workhorse; ADM 3 Cloud (Image), for image generation and editing; and AFM 3 Cloud Pro, for complex reasoning and agentic tool use. verified-as-of: 2026-06-08[^c4-3][^c4-14][^c4-7][^c4-8]
- Apple describes AFM 3 Core as a next-generation approximately 3B dense model and AFM 3 Core Advanced as a natively multimodal 20B sparse model that activates 1–4B parameters per request. The disclosure adds a larger sparse on-device tier alongside the compact dense tier. verified-as-of: 2026-06-08[^c4-3][^c4-7][^c4-8]
- Apple says AFM 3 Core Advanced uses Instruction-Following Pruning: prompt-time routing selects a fixed subset of experts from flash for loading into DRAM, combines routed experts with always-active shared experts, and periodically reselects experts during generation. The 20-billion-parameter model activates 1–4 billion parameters depending on the request. Apple's 2025 IFP paper describes the underlying method as an instruction-conditioned dynamic sparsity mask, but evaluates a distinct 3-billion-activated model rather than AFM 3 Core Advanced.[^c4-3][^c4-11][^c4-12][^c4-9]
- Apple's October 22, 2026 support article says next-generation Apple Intelligence is available with OS 27 releases on eligible devices and labels Siri AI as beta. The earlier June research article described its evaluation results as reflecting models at their current development stage and said improvements would continue during beta; neither page maps availability to each named AFM or ADM variant. (two sources) verified-as-of: 2026-10-22[^c4-6][^c4-3]
- Apple says AFM 3 Cloud upgrades the PT-MoE foundation introduced in 2025 to stabilize training and improve reasoning and recall within the context window. Apple describes ADM 3 Cloud (Image) as a native image creation, editing, and Genmoji model that generalizes across aspect ratios and resolutions, with specialized adapters for downstream experiences such as Spatial Reframing and Image Playground modifications.[^c4-3][^c4-4]
- Google's January 12, 2026 statement says the next generation of Apple Foundation Models would be based on Gemini models and cloud technology. Apple's June announcement calls the five AFM 3 models custom-built in collaboration with Google, and NVIDIA describes the jointly built models as leveraging technologies behind Gemini. These official statements establish collaboration and Gemini-related technology use but do not identify exact checkpoint or weight transfers or specify which internal components were shared. (two sources)[^c4-13][^c4-3][^c4-14]

## Anti-Patterns

- In a July 31, 2026 report, Sentry researcher Drinor Selmanaj said a path traversal in darwin-init let a malicious archive write root-owned files to a writable PCC research VM volume, redirect telemetry, and expose per-request metadata; the researcher reported that Apple’s VRE verifier treated the tampered and clean configurations identically. Apple’s release notes record CVE-2026-20685 and a path-validation fix in PCC release 5E290.3. The report describes a VRE test, not a compromise of production nodes. verified-as-of: 2026-07-31[^c1-3][^c1-8][^c1-9] _(Private Cloud Compute trust architecture and verification)_
