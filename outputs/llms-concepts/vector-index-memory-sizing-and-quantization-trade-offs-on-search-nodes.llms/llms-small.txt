## How it works

- [statement] MongoDB explicitly identifies binary-quantized vector search as a workload in which the bottleneck can move from RAM to storage. Its Search Node sizing article recommends evaluating SSD index capacity, ingestion and indexing demand, query throughput, and latency when selecting a node class. Inference for TCO: smaller required memory alone does not establish which node tier is cheapest. ## Measurements and reference values

- [statement] The cached Atlas deployment guide proposes roughly 4:1 storage:RAM for scalar and 24:1 for binary quantization, and approximates binary index disk size with retained originals as original index size × 25/24. It separately recommends free disk space equal to 125% of estimated index size. These are vendor planning recommendations, not universal compression laws or a substitute for measured capacity. (low confidence) (verified as of 2026-10-14) — https://www.mongodb.com/docs/vector-search/deployment/deployment-options.md
- [statement] Elastic's May 3, 2024 evaluation found average relative nDCG@10 decreases of 0.83% for multilingual E5-small and 0.59% for E5-base after int8 index quantization. This is model- and benchmark-specific evidence of quality loss, not an Atlas result or proof that quantization preserves accuracy universally. (low confidence) — https://www.elastic.co/search-labs/blog/evaluating-scalar-quantization
- [statement] For float32 vectors, N × dimensions × 4 bytes estimates vector payload only; graph and runtime overhead require additional capacity. Qdrant's published 1.5× payload rule includes its graph allowance and must not be substituted as an Atlas sizing constant. ## Comparisons and alternatives

- [statement] MongoDB's documentation distinguishes vector-value compression (4× scalar; 32× binary) from approximately 3.75× and 24× reductions after accounting for an HNSW graph that remains uncompressed. Treat these as documented sizing approximations rather than guaranteed whole-node RAM or bill reductions. - [statement] Retaining original vectors for rescoring creates a memory-versus-I/O trade-off, not free compression. Atlas reads original floats for binary rescoring; Qdrant independently reports that disk reads dominated throughput in a memory-constrained scalar-quantization experiment. The Qdrant result supports the mechanism, not an Atlas latency forecast. ## Facts and statements

- [statement] In the cached Atlas documentation, the Size metric includes graph, compressed vectors and retained originals, whereas Required Memory estimates the index's query-time memory. A quantized index can appear larger on disk while requiring less RAM; node sizing should distinguish these metrics.
