# FlareWarden

> FlareWarden is an uptime monitoring service for agencies, freelancers, and small-to-medium businesses.
> It monitors websites, APIs, SSL certificates, DNS records, and third-party dependencies
> with cross-region validation from multiple global locations. Checks run as frequently as
> every 30 seconds. Pricing from $0/month (free tier) to $229/month.
> https://flarewarden.com

## Product Reference

### Monitor Types

**Uptime Monitors**
- HTTP methods supported: GET (default), POST, PUT, DELETE, HEAD, OPTIONS
- Timeout: 1-30 seconds (default 10)
- Check intervals: 30s, 1min, 5min, 10min, 30min, 1hr (minimum depends on plan)
- States: UP (2xx within timeout), DEGRADED (mixed regional results), DOWN (all regions confirm failure)
- Metrics tracked: availability, HTTP status code, response time (ms), SSL certificate info

**Content Monitors** (7 check types)
1. Text presence/absence (contains or does not contain specific text)
2. Regex pattern matching (extract and validate against patterns)
3. JSON path validation (verify specific values in JSON responses)
4. CSS selector presence (element exists on page)
5. Response header validation (check header values)
6. Status code range (e.g., 200-299)
7. Performance threshold (response time limit)
- Visual Content Picker: point-and-click element selection, no CSS selectors needed
- Options: case-sensitive/insensitive, inverted checks (assert absence), multi-line patterns

**SSL Monitors**
- Automatic for all HTTPS uptime monitors, no separate setup needed
- Tracks: expiration date, certificate changes/renewals, issuer changes, subject changes
- Alert thresholds (configurable): 30 days (warning), 14 days (urgent), 7 days (critical)
- Certificate Transparency log monitoring for subdomain discovery

**DNS Monitors**
- Automatic for all uptime monitors, no separate setup needed
- Record types: A, AAAA, MX, CNAME, TXT, CAA
- Detects: resolution failures (NXDOMAIN, timeouts), IP changes, MX changes, TXT changes (SPF/DKIM)
- WHOIS tracking: registration expiration, registrar changes, nameserver changes, domain status flags

**Dependency Monitors**
- Track third-party services your application depends on
- 40+ integrations across status page platforms, monitoring services, cloud providers, incident management
- Per-dependency severity: Critical (marks site DOWN) or Degraded (marks DEGRADED)
- Auto-discovered via Smart Setup from DNS records and HTML analysis

### Smart Setup

- Enter one URL to automatically configure all monitor types
- 4 stages: website type detection, service discovery (100+ services via DNS/HTML), content pattern detection, plan limit check
- Auto-detected content monitors: error detection (critical), domain theft protection (critical), website tampering (critical), copyright verification (degraded), analytics monitoring (notify)
- Offers status page auto-creation after setup with pre-configured components
- Can re-run on existing monitors to discover new patterns via Content and Dependencies tabs

### Cross-Region Validation

- Checks run from multiple Fly.io regions worldwide
- Failed check triggers validation requests to other regions
- Configurable threshold: validation_requests_required (default: 2)
- States: UP (all pass), DEGRADED (mixed), DOWN (all fail)
- 2-minute timeout per validation (assumed down if no response)
- Prevents false alarms from regional network issues

### Alerts and Notifications

- Channels: email (per user), webhooks (HTTP POST with HMAC-SHA256 signing)
- Alert types (each toggleable per team member): incident started, incident recovery, SSL expiry, SSL changes, certificate detail changes, issuer changes, DNS changes
- Flow: check fails → cross-region validation → incident created → notifications sent → recovery notification on resolution

### Webhooks

- Payload format: JSON with fields: event, timestamp, monitor (id/name/url), incident (id/type/status/started_at/error)
- Supported events: incident.started, incident.recovered, ssl.expiring, ssl.expired, ssl.changed, dns.failed, dns.recovered, monitor.created, monitor.deleted, monitor.paused, monitor.resumed, test.ping
- Security: HMAC-SHA256 signature in X-FlareWarden-Signature header; custom HTTP headers supported
- Delivery: automatic retries with exponential backoff, delivery history with request/response details, manual retry
- Filtering: trigger for all monitors or specific monitors only

### Status Pages

- Real-time component status: operational, degraded, down, maintenance
- Uptime history graph (configurable: 7, 30, or 90 days)
- Incident history with timeline and duration
- Scheduled maintenance display
- Component grouping (e.g., Core Services, Integrations, Regional)
- Subscriber email notifications (double opt-in, one-click unsubscribe)
- Custom branding: logo, colors, favicon, custom domain
- Configurable: timezone, uptime graph days, incident history lookback, powered-by badge toggle

### Status Page API

- Atlassian Statuspage v2 compatible format
- Base URL: https://{slug}.status.flarewarden.com/api/v2/ (or custom domain)
- Endpoints:
  - GET /api/v2/summary.json - Overall status with components
  - GET /api/v2/status.json - Current status indicator
  - GET /api/v2/components.json - All components with status
  - GET /api/v2/incidents.json - All incidents
  - GET /api/v2/incidents/unresolved.json - Active incidents only
  - GET /api/v2/scheduled-maintenances.json - All maintenance
  - GET /api/v2/scheduled-maintenances/upcoming.json - Upcoming only
  - GET /api/v2/scheduled-maintenances/active.json - Currently active
  - POST /api/v2/subscribers - Subscribe email to updates
  - GET /sse/events - Server-Sent Events stream (pushes on status change or ~5 min interval)
- OpenAPI 3.1 spec: https://{slug}.status.flarewarden.com/api/v2/openapi.json

### Team Roles

6 roles with descending permissions:
- Owner: full access including billing, account deletion, data export
- Admin: team management (invite/remove/roles), webhooks, audit logs; no billing or account deletion
- Editor: create/edit/delete monitors, status pages, maintenance; no team or webhook management
- Viewer: read-only access to all monitors and dashboards
- Notify-Only: receives notifications only, no dashboard access
- Monitor-Only: sees only assigned monitors, receives notifications for those monitors

### Incidents

- Types: uptime, content, SSL, DNS, dependency, manual
- Severity: Critical (status → DOWN, affects uptime calculation) or Degraded (status → DEGRADED, tracked separately)
- Lifecycle: started → ongoing → resolved
- Auto-resolution: when check succeeds, content matches, SSL/DNS recovers
- Data tracked: start/end time, duration (auto-calculated), type, severity, error message
- Status page integration: real-time component updates via SSE, subscriber notifications, incident history

### Maintenance Windows

- Pauses monitoring during planned downtime to prevent false alerts
- Appears on status pages as "Under Maintenance" instead of "Down"
- Schedule types: one-time, daily, weekly, biweekly, monthly (by date or by week), last occurrence of month
- States: scheduled → in progress → completed (or cancelled)
- Auto-start and auto-complete at scheduled times with subscriber notifications
- Affected monitors configurable per maintenance window
